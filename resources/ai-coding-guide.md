# 生成AIを活用したGISコーディングガイド

このガイドでは、衛星データ解析のコードを生成AIに書かせる際のプロンプトのコツ、よくあるAIの誤り、検証方法を解説する。

---

## 0. 参考資料（生成AI × 衛星データ解析）

衛星データ解析に生成AIを使う流れ（何を任せてよいか・何を検証すべきか）をより詳しく学びたい人は以下を参照。

| 資料 | 内容 |
|------|------|
| [ChatGPTで始める衛星画像処理入門（Zenn / syu_tan）](https://zenn.dev/syu_tan/books/chatgpt-satellite-image-intro) | 生成AIでJAXAの公式配信経路やSTACからデータを取得し、Google Colabで処理する実践。**「生成AIに任せてよいこと vs 人間・コードで検証すべきこと」**の整理が学べる4章構成（GCOM-CのRGB→NDVI / JAXA Earth APIとSTAC / ChatGPTにColabコードを書かせる） |
| [Google Earth AI × Gemini（XenoSpectrum）](https://xenospectrum.com/google-earth-ai-and-gemini-merge-to-enable-conversations-with-the-earth/) | GoogleのEarth AIプラットフォームとGeminiの統合。地理空間推論・「地球との対話」というAI×衛星データの最新トレンド紹介 |
| [JAXA Earth API](https://www.eorc.jaxa.jp/earthwatching/) | 認証不要で使えるJAXA衛星データ（ALOS・GCOM-C・GSMaP・MODIS等）へのAPIアクセス |

> 💡 **基本原則：** AIは解析作業を高速化するが、**最終的な真偽の判断は人間が行う**。特に衛星データは物理的な意味（スペクトル・散乱機構・座標系・単位）を無視した「もっともらしい」コードをAIが生成しやすい。生成AIを使った解析では以下を必ずチェックする。

QGIS（デスクトップGIS）にAI連携する方法は、本ゼミでは**参考紹介のみ**とする。Colab + GEE/JAXA APIを主環境とし、QGISはデータ確認や成果物共有に使いたい人向けの選択肢として扱う。

## 2. GISコーディングのプロンプトテンプレート

### 基本の型

```
あなたはGoogle Earth EngineとPythonの専門家です。
以下の条件でコードを生成してください。

【タスク】NDVIを計算し、地図表示する
【データセット】COPERNICUS/S2_SR_HARMONIZED
【範囲】福島県浜通り（東経140.5-141.2, 北緯37.2-37.8）
【期間】2024年4月〜9月
【条件】雲カバレッジ20%未満
【出力】NDVIの平均値と地図可視化
```

**ポイント:**
- 「あなたは〜の専門家です」と役割を与える
- タスク・データセット・範囲・期間・条件を箇条書きで明確に指定する
- 出力してほしい形式も明示する

### GEE（earthengine-api）のプロンプト例

#### NDVI計算

```
あなたはGEE（Google Earth Engine）のPython APIの専門家です。
以下のコードを生成してください。

- Sentinel-2 SR_HARMONIZED からNDVIを計算
- 範囲: ee.Geometry.Rectangle([140.5, 37.2, 141.2, 37.8])
- 期間: 2024-04-01 〜 2024-09-30
- 雲20%未満の画像のみ使用
- 最も雲の少ない画像を選んでNDVIを計算
- geemapで地図表示（RGB画像とNDVIを重ねる）
- NDVIの範囲（最小・最大）を表示する
```

#### Sentinel-1 SAR 後方散乱係数

```
あなたはGEEのPython APIの専門家です。
Sentinel-1 SAR GRDデータから後方散乱係数（VH偏波）を取得するコードを書いてください。

- 範囲: ee.Geometry.Rectangle([140.5, 37.2, 141.2, 37.8])
- 期間: 2024-06-01 〜 2024-06-30
- 観測方向: ASCENDING
- 偏波: VH
- geemapで表示（グレースケール）
- 後方散乱係数の範囲（dB単位）も表示
```

> 💡 **注意点:** 上記のように「偏波・観測方向・dB単位」まで指定しないと、AIはHH偏波を使ったり、観測方向を統一せず時系列に混在させたり、S1_GRD（既にdB）に `10*log10()` をさらに適用する「二重変換」を平然と行う。**SARコードは光学以上に指定漏れのリスクが高い**ので検証を怠らないこと。

#### 時系列解析

```
あなたはGEEのPython APIの専門家です。
ある地点のNDVI時系列をプロットするコードを書いてください。

- データセット: COPERNICUS/S2_SR_HARMONIZED
- 地点: 東経140.8, 北緯37.5
- 期間: 2023-01-01 〜 2024-12-31
- 雲20%未満でフィルタ
- 各画像のNDVI中央値を計算し、日付ごとにプロット
- matplotlibで折れ線グラフ
```

### JAXA Earth API のプロンプト例

#### ALOS DEM（標高データ）の取得

```
あなたはJAXA Earth API（jaxa-earth）のPythonの専門家です。
以下のコードを生成してください。

- jaxa-earth ライブラリを使ってALOS AW3D30 DSMを取得
- 範囲: 東経140.5-141.2, 北緯37.2-37.8
- 取得したデータをmatplotlibで表示
- 標高の最小値・最大値・平均値を計算
```

#### GCOM-C NDVI の取得

```
あなたはJAXA Earth API（jaxa-earth）のPythonの専門家です。
以下のコードを生成してください。

- JAXA Earth APIからGCOM-C SGLI NDVI（月次）を取得
- 範囲: 東経140.5-141.2, 北緯37.2-37.8
- 期間: 2024年6月
- データをmatplotlibでカラーマップ表示
- カラーバー付き
```

### VEGA Navigator の質問例

## 3. AIがよく間違えるポイント — ファクトチェックのチェックリスト

生成AIの出力を**そのまま信じない**。以下の観点で必ず検証すること。

### NDVI関連

| チェック項目 | 正しい値・状態 | AIのよくある誤り |
|------------|-------------|----------------|
| NDVIの値域 | **-1 〜 1** の範囲 | 範囲外の値が出ていたら計算式が間違っている |
| Sentinel-2のバンド | B4 = Red, B8 = NIR | B3（Green）をRedと間違えたり、B8A（Narrow NIR）をNIRと誤解したりする |
| 雲フィルタ | `CLOUDY_PIXEL_PERCENTAGE` でフィルタ | `CLOUD_COVER` など存在しないプロパティ名を使うことがある |
| 大気補正 | SR = Surface Reflectance（L2A）が適切 | TOA（Top of Atmosphere）値とSRを混同することがある |

### SAR関連

| チェック項目 | 正しい値・状態 | AIのよくある誤り |
|------------|-------------|----------------|
| 後方散乱係数の値域 | 生のσ0は0〜1程度だが、**dB変換後は-30〜0dB**程度 | 変換なしで-30以下の値を「おかしい」と誤判断することがある |
| 偏波の選択 | Sentinel-1 GRD: VV+VH（デュアル偏波） | 「HH偏波」はSentinel-1では基本的に利用不可 |
| 観測方向の統一 | 時系列解析では **ASCENDING / DESCENDING を統一**する | 混在のままで時系列を解釈し、見かけの変動を「地物変化」と誤認する |
| dBの二重変換 | GEEの `COPERNICUS/S1_GRD` は**既にdB（σ⁰）** | コードが `10*log10()` を二重適用して値域が大幅にずれる |
| 観測モード | 農地解析は **IW（10m・250km）** | 無指定のまま、EW（25m）など粗い画像を使う場合がある |
| スペックルノイズ | フィルタリング（Refined Lee等）や**圃場単位の平均**が必要 | フィルタなしでも「きれいな画像」と誤認識することがある |

### 座標系・CRS関連

| チェック項目 | 正しい値・状態 | AIのよくある誤り |
|------------|-------------|----------------|
| 日本の測地系 | WGS84（EPSG:4326）またはJGD2011（EPSG:6668） | 古いTokyo Datumを使うコードを生成することがある |
| UTMゾーン | 福島は **UTM Zone 54N（EPSG:32654）** | 異なるゾーン（55Nなど）を指定することがある |
| 緯度経度の順序 | GEEでは **経度（lon）, 緯度（lat）** の順 | 逆順（lat, lon）で書くと日本が太平洋の真ん中に飛ぶ |

### その他

| チェック項目 | 注意点 |
|------------|--------|
| GEEのAPIバージョン | AIが古いAPI（`getInfo()` の使い方など）を生成することがある。公式ドキュメントと照らし合わせる |
| 日付のフォーマット | GEEは `YYYY-MM-dd` 形式。AIが違うフォーマットを生成したら修正する |
| エクスポートのパラメータ | `scale`（解像度）の指定を忘れやすい。Sentinel-2なら10mが適切 |

## 4. AIを使ったデバッグの流れ

エラーが出たときの効率的なデバッグ手順。

### Step 1: エラーメッセージをそのままAIに貼る

```
このエラーが発生しました。原因と修正方法を教えてください。

エラーメッセージ:
-----------------------------------------
（ここにエラー全文を貼り付け）
-----------------------------------------
```

### Step 2: AIの修正案をコードに適用する

AIの提案をコピーして実行 → まだエラーが出るなら、新しいエラーメッセージを再度AIに送る。

### Step 3: 値の検証をする

AIが生成したコードが「それっぽい値」を返しているか確認する。

```
生成されたコードが以下の値を返しました。
NDVIの範囲: [-0.5, 0.9]
これは物理的に正しい値ですか？ Sentinel-2の福島農地の6月のNDVIとして妥当ですか？
```

### Step 4: コードの説明を求める

AIに書かせたコードの意味を理解することは最重要。

```
以下のコードの各行が何をしているか、初心者にもわかるように説明してください。

（コードを貼り付け）
```

## 5. このゼミでのAI活用ルール

1. **AIは「コーディングパートナー」であり「答えを出す機械」ではない。**
2. **AIの出したコードは必ず実行し、値の範囲を確認する。**
3. **AIの出したコードは必ず「なぜそう書いたか」を説明させる。**
4. **エラーが出たら、自分で考えてからAIに聞く（5分ルール）。**
5. **AIが間違えた例を演習ログに記録する → それがあなたの学びになる。**
