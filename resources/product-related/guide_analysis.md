# 仮説検証ガイド — 「作った」から「信頼できる」へ

> このガイドは、解析コードが「動いた」後に行う検証プロセスを説明します。
> **「精度指標が高い = 正しい」ではありません。** 物理的・統計的・空間的な整合性を確認して初めて、結果を「信頼して使える」と言えます。

---

## 1. この課題の特性を理解する

福島の農地解析では、**完璧な正解データが存在しません**。農地ポリゴンは「農地の範囲」を示すだけで、「休耕中かどうか」のラベルは持っていないためです。

| | 一般的な機械学習 | 本課題 |
|--|-----------|-------|
| 正解データ | あらかじめ人手ラベル付きで存在する | 存在しない |
| 検証方法 | テストセットとモデル出力の比較 | 疑似ラベル ＋ 目視確認 |
| 精度指標の意味 | 真の正解との一致度 | 疑似ラベルとの一致度（上限がある） |
| 伝えるべき不確実性 | モデルの予測誤差 | モデルの誤差 ＋ 疑似ラベル自体の不確かさ |

この**限界を正直に伝えること**が、技術レポートでも自治体向けスライドでも評価されます。

## 2. 入力になる field_features.csv の列

このガイドのコードは、W7 で作成した `field_features.csv` をそのまま入力にします。列名は**すべて小文字**です。書き写すときはスペルに注意してください（大文字にすると `KeyError` になります）。

| 列名 | 意味 |
|------|------|
| `field_id` | 圃場ID（1筆に1つ） |
| `year` | 対象年。**1行 = 1筆 × 1年** |
| `ndvi_max` / `ndvi_min` / `ndvi_amplitude` | 年間の最大・最小・振幅NDVI |
| `ndvi_may` / `ndvi_aug` | 5月・8月の平均NDVI |
| `ndvi_max_month` / `growth_slope` | NDVIピークの月・生育の立ち上がり勾配 |
| `vh_may` / `vh_aug` / `vh_min` | 5月・8月・年間最小の σ⁰(VH)（dB・必ず負値） |
| `vh_amplitude` / `vh_temporal_diff` | VHの季節振幅・8月−5月の差分 |
| `vv_vh_may` / `vv_vh_aug` | 5月・8月の VV と VH の**差**（dB）。dB では比は差になる |

> **確認方法**：`print(df.columns.tolist())` を最初に1回実行して、手元のCSVの列名と照合してください。

## 3. 疑似ラベル（Pseudo-Label）の作り方

疑似ラベルとは、「正解ラベルがない中で、物理的ルールに基づいて自分たちが定義した仮の正解」です。

### 疑似ラベルの定義例

| カテゴリ | 条件の例 | 物理的な根拠 |
|---------|---------|------------|
| 作付地（疑） | `vh_may` ≦ -18 dB **かつ** `ndvi_aug` ≧ 0.70 | 5月の湛水でSAR後方散乱が下がる ＋ 8月の稲の繁茂でNDVIが上がる |
| 休耕地（疑） | `ndvi_max` ＜ 0.25 | 生育期を通してNDVIのピークが現れない |
| グレーゾーン | 上記どちらにも当てはまらない | 確信度が低い：現地確認が必要 |

> **重要**：この閾値（-18.0 / 0.70 / 0.25）は出発点の例です。チームが自分たちの物理仮説とデータを見て決める値であり、変えて構いません。ただし**変えたら再現性ヘッダに記録してください**（`guide_camp.md` §5）。解析計画書 Step2 の仮説と整合しているかも必ず確認します。

### 疑似ラベルを使う際の注意点

疑似ラベルで学習・評価したモデルは、**疑似ラベルの定義上の誤りをそのまま引き継ぎます**。精度評価の数値（F1スコアなど）は、あくまで「疑似ラベルとの一致度」であり、「真の正解との一致度」ではありません。この制約を必ず技術レポートと自治体向けスライドで説明してください。

## 4. 精度評価の手順（4ステップ）

### Step 1: 疑似ラベルの定義と field_features.csv への追加

```python
import pandas as pd

df = pd.read_csv('field_features.csv')
print(df.columns.tolist())        # 列名を最初に必ず確認する
df = df[df['year'] == 2024]       # 解析対象年に絞る（1筆=1行になる）

# ---- 疑似ラベルの閾値（チームで決めて再現性ヘッダにも記録する） ----
VH_FLOOD_THRESH  = -18.0   # dB（5月の湛水判定）
NDVI_HIGH_THRESH =   0.70  # 8月の作付判定
NDVI_LOW_THRESH  =   0.25  # 年間最大が低い＝休耕

df['pseudo_label'] = 'グレーゾーン'
df.loc[
    (df['vh_may'] <= VH_FLOOD_THRESH) & (df['ndvi_aug'] >= NDVI_HIGH_THRESH),
    'pseudo_label'
] = '作付（疑）'
df.loc[df['ndvi_max'] < NDVI_LOW_THRESH, 'pseudo_label'] = '休耕（疑）'

print(df['pseudo_label'].value_counts())
```

#### 全部「グレーゾーン」になったときは（最初に必ず起きます）

上の閾値は**水稲を想定した一般的な値**です。自分たちのエリア・年・前処理では、1筆も条件を満たさないことがよくあります。`value_counts()` がグレーゾーンばかりなら、**閾値がデータに合っていない**というだけで、コードは壊れていません。

まず自分のデータの分布を見てください。

```python
print(df[['ndvi_max', 'ndvi_aug', 'vh_may', 'ndvi_amplitude']].describe())
```

- `ndvi_aug` の最大値が 0.70 に届いていない → `NDVI_HIGH_THRESH` を下げる（例：中央値あたり）
- `vh_may` が全体的に -18 dB より低い／高い → `VH_FLOOD_THRESH` をデータの分布に合わせる
- `ndvi_max` の最小値が 0.25 より大きい → `NDVI_LOW_THRESH` を上げる

```python
# 例：データの分布から閾値を決める（分位点を使う）
NDVI_HIGH_THRESH = df['ndvi_aug'].quantile(0.70)   # 上位30%を「作付」候補に
NDVI_LOW_THRESH  = df['ndvi_max'].quantile(0.30)   # 下位30%を「休耕」候補に
VH_FLOOD_THRESH  = df['vh_may'].quantile(0.50)
```

> **注意**：分位点で決めた閾値は「とりあえず動かす」ためのものです。最終的には**物理的な根拠**（5月の湛水・8月の出穂）で説明できる値に戻してください。分位点のまま提出すると、技術レポート §2「物理仮説」との整合が取れなくなります。決めた値は必ず再現性ヘッダに記録します。

> **サンプルデータで練習する場合**：`tutorials/field_features.csv`（サンプル6筆）は筆数が少なく、例の閾値では全筆がグレーゾーンになります。手順の確認が目的なので、上の分位点の方法で閾値を仮置きして先に進んでください。

### Step 2: 判別結果（pred_label）と確信度（confidence）を作る

`pseudo_label` は「仮の正解」です。これと比べる**自分たちの判別結果**が別に必要です。作り方はチームの手法によって2通りあります。

**(a) ルールベースで判別しているチーム**

疑似ラベルとは別の特徴量（例：`ndvi_amplitude`）で判定し、閾値からの距離を確信度にします。

```python
import numpy as np

# 判別ロジック：生育の振幅が小さい圃場を「休耕」とみなす
AMP_THRESH = 0.30
df['pred_label'] = np.where(df['ndvi_amplitude'] < AMP_THRESH, '休耕', '作付')

# 確信度 = 閾値からどれだけ離れているか（0〜1に正規化）
dist = (df['ndvi_amplitude'] - AMP_THRESH).abs()
df['confidence'] = (dist / dist.max()).clip(0, 1)
```

**(b) 機械学習を使っているチーム**

`predict` が判別結果、`predict_proba` の最大値が確信度になります。

```python
from sklearn.ensemble import RandomForestClassifier

FEATURES = ['ndvi_max', 'ndvi_amplitude', 'ndvi_may', 'ndvi_aug',
            'growth_slope', 'vh_may', 'vh_aug', 'vh_min', 'vh_amplitude']

train = df[df['pseudo_label'] != 'グレーゾーン']          # 疑似ラベルが付いた筆だけで学習
clf = RandomForestClassifier(n_estimators=200, random_state=42)
clf.fit(train[FEATURES], train['pseudo_label'])

df['pred_label'] = clf.predict(df[FEATURES])
df['confidence'] = clf.predict_proba(df[FEATURES]).max(axis=1)
```

> **注意（時空間リーク）**：学習と検証を分ける場合は、同じ `field_id` が両方に入らないように分割してください。同じ圃場が train と validation の両方にあると、モデルは「記憶」するだけになり、精度が実際より高く見えます。

### Step 3: 混同行列と F1 / Precision / Recall を計算する

```python
from sklearn.metrics import confusion_matrix, classification_report

# グレーゾーン（判定を保留した筆）を除いて評価する
ev = df[df['pseudo_label'] != 'グレーゾーン']
assert len(ev) > 0, 'グレーゾーンしかない。Step1 に戻って閾値を調整すること'

cm = confusion_matrix(ev['pseudo_label'], ev['pred_label'],
                      labels=['作付（疑）', '休耕（疑）'])
print(cm)
print(classification_report(ev['pseudo_label'], ev['pred_label']))
```

| 指標 | 意味 | 現場での解釈 |
|------|------|------------|
| **Precision（適合率）** | 「休耕」と判定したうち本当に休耕の割合 | 低いと「空振り」が多い（確認に行ったら作付だった） |
| **Recall（再現率）** | 実際の休耕地のうち「休耕」と正しく判定した割合 | 低いと「見落とし」が多い（休耕地を見逃した） |
| **F1スコア** | Precision と Recall の調和平均 | バランスの取れた総合指標 |
| **IoU** | 予測エリアと正解エリアの重なり率 | 空間的な精度評価（地図で確認しやすい） |

### Step 4: FP と FN の現場コストを考え、閾値を決める

FP（偽陽性）と FN（偽陰性）のコストは非対称です。どちらが問題かをチームで議論してください。

| 誤り | 数式上の意味 | 農地監視での影響 |
|------|------------|--------------|
| **FP（偽陽性）** | 作付地を「休耕」と誤判定 | 農家への不要な調査・通知（信頼を損ねる） |
| **FN（偽陰性）** | 休耕地を「作付」と誤判定 | 農地台帳更新の失敗・休耕地の見落とし |

確信度の閾値を変えることで、「自信を持って判定した筆」と「現地確認に回す筆（要確認）」の割合を調整できます。

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.metrics import precision_score, recall_score, f1_score

# 確信度は max(p, 1-p) なので 0.5〜1.0 の範囲に入る。
# 0.5 未満の閾値を振っても全件が通過して意味がないので、0.50 から始める。
rows = []
for t in np.arange(0.50, 0.96, 0.05):
    sub = ev[ev['confidence'] >= t]          # 確信度が閾値以上の筆だけを「判定済み」とみなす
    if len(sub) == 0:
        continue
    rows.append({
        'threshold': round(t, 2),
        'precision': precision_score(sub['pseudo_label'], sub['pred_label'],
                                     pos_label='休耕（疑）', zero_division=0),
        'recall':    recall_score(sub['pseudo_label'], sub['pred_label'],
                                  pos_label='休耕（疑）', zero_division=0),
        'f1':        f1_score(sub['pseudo_label'], sub['pred_label'],
                              pos_label='休耕（疑）', zero_division=0),
        'r_要確認率': 1 - len(sub) / len(ev),   # 判定を保留した割合 = 現地確認が必要な割合
    })

res = pd.DataFrame(rows)
print(res)

plt.plot(res['threshold'], res['f1'], marker='o')
plt.xlabel('確信度の閾値（0.5〜1.0）'); plt.ylabel('F1'); plt.grid(True)
plt.show()
# → 値が安定している「プラトー」の範囲が安全な閾値域
```

> **ポイント**：F1が最大の閾値が「運用上の最適」とは限りません。農地監視では一般的に見落とし（FN）のコストが高く、Recallを優先して閾値を低めに設定することがあります。チームで「なぜその閾値を選んだか」を言語化して、解析計画書 Step5 に記録してください。

## 5. ファクトチェック3層

精度評価に加えて、以下の3層でファクトチェックを行います。W8 の演習、合宿 Day1 のクロスレビュー、Day2 の中間レビューで使うチェックリストです。

### ① 物理的ファクトチェック

「センサの特性と観測条件から見て、この結果は物理的に説明できるか？」

- [ ] **バンド・偏波は正しいか？**（NDVI なら B8/B4、SAR なら VV/VH。B5 や VV のみで NDVI を計算していないか）
- [ ] **単位は正しいか？**（Sentinel-1 GRD は既に dB スケール。線形値に変換していないか。`vh_aug` が正値なら変換ミス）
- [ ] **軌道方向は統一されているか？**（ASC/DESC の混在で時系列ノイズが生じる。`orbitProperties_pass == 'DESCENDING'` でフィルタしたか）
- [ ] **観測時期は物理仮説と整合しているか？**（5月の湛水・8月の NDVI ピークを捉えている時期のデータがあるか）
- [ ] **異常に明るい / 暗い値がある場合、散乱機構で説明できるか？**（圃場の隅に水路や道路が混入していないか）

### ② 統計的ファクトチェック

「疑似ラベルの定義と使い方に誤りがないか？」

- [ ] **時空間リーク**：訓練データと検証データに同じ `field_id`（圃場ID）が入っていないか？（同じ圃場が train と validation 両方に入ると、モデルは記憶するだけになる）
- [ ] **疑似ラベルの定義が物理仮説と一致しているか？**（解析計画書 Step2 の仮説と比べて確認する）
- [ ] **サンプル数が偏っていないか？**（「休耕地（疑）」のサンプルが極端に少ないと、モデルが「作付」に偏る不均衡問題が起きる）

### ③ 空間的ファクトチェック

「地図上で見たとき、空間的に不自然な結果はないか？」

- [ ] **隣接する圃場で全く逆の結果になっていないか？**（境界のアーティファクトの可能性）
- [ ] **ミクセル問題**：圃場の端のピクセルに道路・水路の影響が混入していないか？（Sentinel-1/2 の 10 m 解像度では、小面積の圃場ほど影響が大きい）
- [ ] **解析結果を geemap や QGIS で地図表示して、現地の様子と一致しているか？**

## 6. 不確実性の言語化

「結果がどこまで信頼できるか」を、専門家と非専門家向けにそれぞれ言語化します。

### 専門家向け（技術レポートに記載）

```
本解析は疑似ラベルに基づく評価であり、精度指標（F1: X.XX）は
疑似ラベルとの一致度を示す。真の休耕地ラベルとの比較は行って
いないため、実際の精度はこの数値と異なる可能性がある。

また、X月X日の観測では雲の影響により△△圃場の観測値が欠損した。
閾値 t = 0.X のとき Precision = X.XX / Recall = X.XX であり、
FN コスト（見落とし）を重視して t = 0.X を採用した。
```

### 非専門家向け（自治体向けスライドに記載）

```
【確認が必要なエリア】
今回の解析では、全圃場のうち約 X% が「判定の確信度が低い
エリア」として特定されました。このエリアについては現地確認を
推奨します。それ以外の Y% については解析精度が高く、現地確認の
優先度を下げることができます。
```

## 付録：AIへの5つの問い（コードレビュー時の確認事項）

生成AIが出力したコードをそのまま使う前に、以下を確認してください（`exercises/analysis_doc.md` §2 より）。

1. **単位は正しいか？** … dB（S1_GRD は既に dB）/ 反射率 / 線形？
2. **バンド・偏波は正しいか？** … NDVI なら B8 & B4、SAR なら VV / VH？
3. **座標系（CRS）は揃っているか？** … EPSG:32654 で全レイヤが一致しているか？
4. **軌道方向・観測モードは統一されているか？** … DESCENDING に統一、観測モードは IW？
5. **観測時期・雲量は妥当か？** … 季節サイクルに合うか、雲フィルタ（`CLOUDY_PIXEL_PERCENTAGE < 20`）はあるか？
