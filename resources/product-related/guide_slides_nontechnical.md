# 非専門家向けスライドガイド — 自治体へ価値を届ける

> このガイドは、合宿 Day 3〜Day 5 で作成する「自治体向け提案スライド（8〜10枚）」の構成と内容を説明します。
> **技術的な正確さよりも、「農政担当者が聞いて、次に何をすればよいかが分かる」かどうかを最優先にしてください。**

---

## 1. 誰に、何を伝えるか

| 項目 | 内容 |
|------|------|
| 想定する聴衆 | 相馬市・南相馬市の農政担当者（衛星やSARを知らない） |
| 聴衆の知識レベル | 農業・農地行政の実務は詳しい。衛星・NDVI・dBは知らない |
| この発表で達成したいこと | 「衛星データを農地監視に使うと、現地調査コストが減らせる」と納得してもらう |
| 評価されること | 結論が明確か・コストメリットが具体的か・限界を正直に伝えているか |

**NG な伝え方**：「SARはC-bandの合成開口レーダーでVV/VH偏波を使い...」

**OK な伝え方**：「悪天候でも農地の状態を上空から定期的に確認できるシステムです」

## 2. 最初の30秒で「自分たちのチームの特色」を述べる

**3チームとも課題は同じです**（相馬市・南相馬市の作付/休耕判別、同じデータ、同じエリア）。
聴衆は同じ日に3チームの発表を続けて聞きます。**何も言わなければ「さっきと同じ話」に聞こえます。**

だから発表の冒頭で、**「自分たちは何を大事にして、どこにフォーカスしたのか」**を必ず述べてください。

### 言い方の型

```
私たちは〈長期的に解決したいこと〉を目指しています。
今回はその第一歩として〈今回やったこと〉に取り組みました。
だからこの発表では〈フォーカスした観点〉を重視しています。
```

### 記入例

> 「私たちは**日本の農地の課題を長期的に解決したい**と考えています。
> 今回はその第一歩として、**相馬市の農地でケーススタディ**を行いました。
> だからこの発表では、**他の自治体でも同じ手順で再現できること（再現性）**にフォーカスしています。」

### フォーカスの切り口（例）

| 切り口 | どんなチームに向くか | 発表で強調すること |
|-------|-----------------|----------------|
| **再現性** | 手順・パラメータを丁寧に固めた | 「他の市町村でも同じ手順で回せる」 |
| **コスト** | 費用対効果を詰めた | 「現地確認が何時間減るか」 |
| **精度** | 検証・閾値設計に時間をかけた | 「どこまで信頼できるかを数字で言える」 |
| **現場運用のしやすさ** | 出力の形（優先リスト・地図）を工夫した | 「担当者が明日から使える形になっている」 |
| **拡張性** | 他作物・他地域への展開を考えた | 「大豆にも、隣の市にも広げられる」 |

> **注意**：特色は「がんばったこと」ではなく「**聴衆にとっての意味**」で語ってください。
> 「再現性を頑張りました」ではなく「他の自治体でも同じ手順で回せます」と言い換えます。

## 3. スライドは2段階で作る（レビュー版 → 完成版）

いきなり完成版を作ろうとすると、Day 3 のメンターレビューに間に合いません。次の2段階で進めてください。

| | **レビュー版（Day 3 午前まで）** | **完成版（Day 4 終了まで）** |
|--|------------------------------|---------------------------|
| 枚数 | 8〜10枚（全枚数そろっていること） | 8〜10枚 |
| 各スライドの中身 | タイトル ＋ 言いたいこと1行 ＋ 「ここに何の図を置くか」のメモ | 本文・図・凡例まで完成 |
| 図 | 空欄・手描き・仮の図でよい | 判別マップ・グラフの実物 |
| 数字 | 暫定値・空欄（`X%` のまま）でよい | 自チームの実測値 |
| 目的 | **メンターに「構成と論点が正しいか」を見てもらう** | 発表する |
| 完成度の目安 | 50% | 100% |

> **レビュー版で一番大事なのは「全枚数そろっていること」です。** 1〜3枚目だけ作り込んで後半が白紙、という状態が最も指摘を受けにくく、もったいないパターンです。薄くてもよいので最後まで通してください。

## 4. スライド構成テンプレート（8〜10枚）

### Slide 1 — タイトルと課題の設定

**タイトル例**：「衛星で見る福島の農地 — AIと衛星データで作付け変化を把握する」

**入れること**：
- チーム名・発表者名
- **チームの立ち位置（1〜2行）** … §2 の型で書く。**このスライドの主役はここ**
- 対象エリア：相馬市・南相馬市
- 解決しようとした課題（1行）：例「農地台帳の更新コストが高く、休耕地の把握が追いついていない」

**ポイント**：技術の説明は不要。「誰の何の課題か」と「自分たちはどこにフォーカスしたか」を提示する。
3チームとも課題は同じなので、**立ち位置がこのスライドの差別化点**になる。

---

### Slide 2 — 問題の背景

**入れること**：
- 現在の農地確認方法（現地目視・台帳照合）とそのコスト・課題
- 「なぜ今これが必要か」（震災復興・担い手不足・農地集約の文脈）
- As-Is（現状）の概算：例「1筆あたり ◯◯円 × N筆 = 年間約◯◯万円」

**ポイント**：現場の人が「そうそう、これが困っている」と感じる言葉を使う。数字は公開資料（e-Stat等）から引用し、出典を添える。

---

### Slide 3 — 提案のアプローチ

**入れること**：
- 「衛星データで何ができるか」を1〜2行で（専門用語は最小限）
- 使ったデータと期間の概要
- 提案の全体像：「衛星で一次スクリーニング → 要確認エリアを絞り込み → 現地確認を集中投下」

**ポイント**：技術説明ではなく「何ができるようになるか」を中心に。フローを図で示すと分かりやすい。

---

### Slide 4〜5 — 解析結果の地図（1〜2枚）

**入れること**：
- 判別マップ（作付/休耕/グレーゾーンを色分けした地図）
- 色の意味を日本語の凡例で明記：例「赤 = 休耕の可能性が高い／黄 = 確認が必要／緑 = 作付中」
- 対象エリアの圃場数・休耕地疑いの割合

**ポイント**：
- 全体地図 1枚 ＋ 特定エリアにズームインした地図 1枚の2枚構成にすると伝わりやすい
- 地図の中に吹き出し・矢印で「このエリアは特に注目」と直接書く
- 精度指標（F1スコアなど）はこのスライドに入れない

---

### Slide 6 — コスト削減の試算

**入れること**：
- As-Is（現在）：全圃場を現地確認する場合のコスト計算
- To-Be（提案後）：衛星で一次スクリーニング → 要確認エリアのみ現地確認
- 削減できるコストの概算

**テンプレート**：

```
現在（As-Is）：
N筆 × c円/筆 = 約X万円/年

提案後（To-Be）：
衛星解析コスト（年間） + 要確認率 r × N × c円/筆
r = 20%（全圃場の20%だけ現地確認）の場合：約Y万円/年

→ 削減効果：約Z万円/年（W%削減）
   ※ r は解析精度次第で変わります（詳細は別紙）
```

**ポイント**：「r（要確認率）は解析精度次第で変わる」ことを正直に添記する。数字だけを強調せず、前提条件を示すことで信頼感が生まれる。

---

### Slide 7 — 解析の限界と確認が必要なエリア

**入れること**：
- 解析で判定できなかったエリアとその割合：例「全圃場の約 X% は判定の確信度が低い」
- その理由を1〜2行で（専門用語なし）
  - 例：「秋の収穫後の農地は草地と見分けがつきにくい場合があります」
  - 例：「雲がかかっていた時期はデータを利用できませんでした」
- グレーゾーンの圃場リスト（優先順位付き）

**ポイント**：限界を隠すと信頼を損ねます。「分からないこと」を正直に言えるチームが信頼されます。

---

### Slide 8 — 解析の信頼性と根拠

**入れること**：
- 「この解析はどれくらい信頼できるか」を平易な言葉で
  - 例：「判定に高い確信があるエリアでは、目視確認との一致率が約 Y% でした」
- データの出どころ（Sentinel-1/2 はESAが無償提供、農地ポリゴンは農水省公開データ）
- 継続的なモニタリングの可能性：「毎年同じ方法で更新できます」

**ポイント**：「AIが出した結果を人間がチェックしている」ことを伝えると信頼感が上がります。

---

### Slide 9 — 次のステップと提案

**入れること**：
- 自治体に次にやってほしいこと（具体的なアクション）
  - 例：「今年度のモニタリングデータと現地確認結果の照合調査」
  - 例：「農地台帳更新業務への組み込みの検討」
- 今後の展開案（3〜5項目）
  - 来年度以降の自動更新フロー
  - 他市町村への展開可能性

**ポイント**：「提案で終わり」ではなく「次にどうするか」を提示する。

---

### Slide 10（任意）— 中長期ビジョン / Q&A 補足

**中長期ビジョン**：5〜10年後の農地管理の姿、衛星データが農政業務の一部になった世界のイメージ

**Q&A 補足**（よくある質問への先回り）：
- 「リアルタイムで見られるのか？」→ 衛星の再訪周期（Sentinel: 約6日）があるため、リアルタイムではなく定期更新（月1〜2回程度）になります
- 「コストはかかるのか？」→ データ自体は無料ですが、解析には計算環境のコストがかかります
- 「ドローンの方が正確では？」→ 面積カバレッジ・アーカイブ性・コストで衛星が優位です

## 5. NG / OK の比較例

### 技術説明の言い換え

| NG（技術用語そのまま） | OK（平易な言葉） |
|----------------------|----------------|
| σ⁰（後方散乱係数）が -18 dB 以下の場合に湛水を検出した | 水田の水張り時期に衛星の信号が特徴的に変化することを利用して検出しました |
| VV/VH偏波のC-band SARを使用した | 2種類の電波を組み合わせることで晴天・曇天を問わず解析できます |
| F1スコアが 0.82 で高精度だった | 解析精度を確認したところ、約8割の農地で正しく判別できました（技術詳細は別紙） |
| 疑似ラベルを使った自己教師あり学習を実施した | 過去の衛星データのパターンから「休耕地らしさ」の基準を自動的に作りました |

### 地図の見せ方

| NG | OK |
|----|-----|
| 凡例が英語（Fallow / Cultivated） | 凡例が日本語（休耕地の可能性 / 作付中 / 要確認） |
| 地図に何の説明もなく、見る人が自分で解釈しなければならない | 吹き出し・矢印で「このエリアは特に注目」と地図内に直接書く |
| 相馬市全体が見える広域地図だけ | 圃場レベルにズームインした地図も1枚加える |

## 付録：衛星データの強みと制約（Q&Aで使える説明）

**伝えるべき強み**：
- **広域性**：広い範囲を一度にカバーできる（ドローンでは非現実的な面積）
- **アーカイブ性**：過去のデータに遡って比較・分析できる
- **定期性**：同じ方法で毎年繰り返せる（比較可能）
- **コスト**：Sentinel-1/2 のデータ自体は無料

**正直に伝えるべき制約**：
- データの頻度：再訪周期の制約がある（Sentinel: 約6日、同一軌道では12日以上）
- 空間解像度：10m解像度のため、小面積の圃場は精度が落ちる
- 雲の影響：光学（Sentinel-2）は曇天・雨天時に使えない（SARは使える）
