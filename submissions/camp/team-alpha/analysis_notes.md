## 2. 物理仮説（Step2・専門家観点）

**なぜ光学＋SAR で判別できるか**

作付地は NDVI が7月にピークへ上昇する一方、SAR の σ⁰ は5月に湛水（表面散乱）で急落し、7〜8月に生育（体積散乱・ダブルバウンス）で急上昇する。休耕地はどちらの指標も年間を通してほとんど変化しない。

光学（NDVI）だけでは、6〜7月の曇天時にデータが欠損し、生育期の変化を安定して追えない。SAR だけでは、5月の湛水シグナルは捉えられても、7〜8月の「植生の質」（健全な生育か、単なる雑草か）を NDVI ほど直接的には判断できない。

そのため、光学と SAR を組み合わせることで、天候に左右されず（SAR の強み）、かつ植生の活性度も評価できる（光学の強み）、互いの弱点を補い合った判別が可能になる。

**検出する季節イベントと観測量のペア**

| 時期 | 季節イベント | 観測量の変化 | 物理機構 |
|------|-------------|-------------|---------|
| 5月 | 湛水（代かき・田植え） | **VH σ⁰ が急落** | 水面での鏡面反射により電波が衛星に戻らない |
| 7月 | 生育 | **NDVI がピークへ上昇** | 葉の海綿状組織による近赤外の強い構造反射 |
| 7〜8月 | 生育最盛期 | **VH σ⁰ が急上昇** | 茎葉による体積散乱、および茎と水面のダブルバウンス |
| 通年 | 休耕 | **NDVI・σ⁰ ともにほぼ変化なし** | 湛水も繁茂も起こらないため季節変動が生じない |

## 3. 使用データと前処理（Step3・専門家観点）

### Sentinel-2（光学）

- NDVI には **B8（NIR）と B4（Red）** を使用
- CRS は **UTM（EPSG:32654）に統一**し、筆ポリゴンとのズレを防ぐ
- 雲量フィルタは **`CLOUDY_PIXEL_PERCENTAGE < 20`** を適用し、曇りの多いシーンを除外する

最低限上記のデータを使用するが、もっと利用できるので都度利用したい。
B11とか、他の指標とそれらの演算で求められる指標も含めて利用を検討する。ただし、たくさん利用して判断がしづらくなるのは
本末転倒である。そのため利用するのは以下の２パターンに集約する。
１、NDVIよりも詳細に判断が必要な場合
２、NDVIと１で追加した情報から考えて予測できることを確認しバグチェックを行うためのデータ

### Sentinel-1（SAR）

- 偏波は **VH** を使用（体積散乱に敏感で植生の生育状況を捉えやすい）
- 軌道は **DESCENDING に統一**し、昇交・降交の混在による入射角の不整合を防ぐ。ASCENDING でも良いと思われる。一方に統一さえすれば良い
- 観測モードは **IW**
- `COPERNICUS/S1_GRD` は既に dB に変換済みのため、**`10*log10()` による二重変換は行わない**
- 観測期間は **5月〜8月**。5月は湛水による急落を捉え、8月は生育最盛期のピーク（体積散乱による高い値）まで含めることで、「谷 → 上昇 → ピーク」という作付地特有の変化パターン全体を観測できるようにする

**【軌道の検証】**

GEE Code Editor で、ROI 内の DESCENDING 軌道の `relativeOrbitNumber` を集計したところ、**2024年4〜8月の全13観測がすべて軌道番号46**であった。このため、DESCENDING 軌道・軌道番号46への統一のみで、実質的に単一軌道への固定が達成されていることを確認済み。

これってCLIでGEE Code Editorに入ることが可能であれば確認して欲しい。

**【限界】**

Sentinel-1 の観測間隔は約12日おきであり、田植え（代かき・湛水）のような数日で終わる短いイベントが、たまたま観測日と観測日の間で発生・終了した場合、SAR だけでは「谷」を検出できない可能性がある。この場合、実際には作付けされているにもかかわらず、湛水シグナルが見られないために誤って休耕地と判定してしまうリスクがある。

**【対策】**

この限界を補うため、SAR 単独ではなく光学（NDVI）による生育確認を必ず併用する。SAR で湛水シグナルが検出できなくても、その後の時期に NDVI の上昇（生育開始）が確認できれば、作付けが行われたと判断できるようにする。

この生育確認を行う際に追加で指標を利用するのが必要かもしれない。
また、その期間が雲で覆われていて観測できない場合はどうするか追加で検証する必要がありそう。

## 4. 解析手法（Step4）

### 候補エリアの比較（相馬市 vs 南相馬市）

| 観点 | 相馬市 | 南相馬市 |
|------|--------|---------|
| 農地重心の数 | 2箇所（西・東） | 1箇所のみ |
| ROI の規模 | 約3.5 km × 2.1 km | 約2.6 km × 1.3 km |
| 水場の参照点 | 5件（河川4＋潟湖1）すべて確定座標 | 7件だが、うち2件（新田川・渋佐川河口）が要確定の概算値 |
| 森林の参照点 | 5件、すべて確定座標 | 4件、確定座標 |
| 座標の信頼度 | 全点 OSM 由来で確定 | 一部に不確実性あり |

**なぜ相馬市が優れていると考えるか**

1. **2つの農地重心があり、Step5 の検証がそのまま実行できる。** Step5 では「候補地点を1〜2箇所選んで True Color 画像で目視確認する」と決めた。相馬市には西と東、地理的に離れた2つの農地重心が既に用意されているので、これを使えば1つの市内で東西の比較検証ができる。同じ市内でも場所によって作付け状況が異なる可能性があるため、良い検証になる。

2. **「恒常的な水面」との比較材料がある（相馬市だけの強み）。** 相馬市の参照点には松川浦（潟湖）という、季節に関係なく1年中水がある場所が含まれている。これは Step2 の仮説（水田は5月だけ暗い、休耕地は変化しない）を検証する上で良いテストケースになる。松川浦（通年水面）の σ⁰ は季節を問わずずっと暗いはず。もし解析コードがこの松川浦を誤って「5月に暗くなる水田」と判定してしまったら、ROI 設定に農地以外を含んでいるというバグ発見の手がかりになる。つまり松川浦は「正しく農地だけを見られているか」を確認するための**対照点（コントロール）**として使える。

3. **座標データの信頼度が高い。** 南相馬市側は北側の2つの河口座標が「要確定」の概算値のままで、検証に使うには座標を確定させる追加作業が必要になる。

**一方で、南相馬市を完全に外さない方がよい理由**

B3 で「田耕地 **5,690 ha** に対し水稲 950 ha」という統計的なコントラストの強さを根拠に南相馬市を選んだ（田耕地面積は e-Stat 実ファイルの値。水稲作付面積は出典未特定）。この根拠は相馬市にはない強み。データの質は相馬市の方が高いが、「作付 / 休耕の差が大きく出やすいエリア」という点では南相馬市の統計的裏付けも活かしたい。

> **出典**: 上表の農地重心・水場・森林の参照点は `resources/候補エリア選定_相馬南相馬.md` に基づく。

### 【選択した手法】

**時系列解析**

### 【選択理由】

Step2 で立てた物理仮説（SAR の σ⁰ は5月に湛水で急落し7〜8月の生育で急上昇する一方、休耕地はこの変化を示さない）は、本質的に「時間軸に沿った変化のパターン」そのものである。したがって、2時点の差分（変化検出）ではなく、複数観測点をつなげた時系列解析によって、この仮説を最も直接的に検証できる。

### 【全体設計（チームの基本方針）】

**時系列ルールベース・2系統統合型。** 各筆について Sentinel-1（VH 時系列）と Sentinel-2（NDVI 時系列）の両方を取得し、両者を突き合わせて判定する。SAR 単独・光学単独ではなく統合する理由は、Step3 で明記した「SAR は観測間隔（約12日おき）の隙間で短期間の湛水イベントを見逃す可能性がある」という限界を、光学による生育確認で補うためである。

### 【処理パイプライン】

**Step4-1. 軌道の固定**

DESCENDING 軌道に統一する。GEE で実際に ROI 内の `relativeOrbitNumber` を集計したところ、2024年4〜8月の全13観測がすべて軌道番号46であることを確認済み。このため、DESCENDING 軌道・軌道番号46への統一のみで、実質的に単一軌道への固定が達成されている。

ここの期間がずれているが、5月から8月で集計するように変更する。もし、GEEをCLIで叩けるなら見てみて欲しい。

**Step4-2. SAR側: 湛水イベントの検出**

各筆で VH σ⁰ の時系列を取得し、前後の観測点と比べて急激な低下（目安: **5 dB 以上**の落ち込み）があれば、その期間を「推定湛水期」として記録する。

**Step4-3. 光学側: 生育開始の検出**

同じ筆で NDVI 時系列を取得し、NDVI が閾値（**0.4**）を超えた最初の日付を「推定生育開始日」として記録する。雲量フィルタ（`CLOUDY_PIXEL_PERCENTAGE < 20`）を通過したシーンのみを使用する。

**Step4-4. 統合・判定（3段階分類）**

SAR と光学の結果を突き合わせ、以下の3段階に分類する。二択で無理に判定せず、SAR 単独で判断がつかないケースを明確に切り分けるのが設計上のポイントである。

| 分類 | 条件 | 位置づけ |
|------|------|---------|
| **作付けの可能性が高い** | SAR で明確な湛水シグナル（5 dB 以上の急落）が見られる筆 | — |
| **要確認**（SAR不検出・光学で生育あり） | SAR では湛水シグナルが見られないが、その後 NDVI の上昇（生育開始）が確認できる筆 | 観測間隔の隙間で湛水イベントを見逃した可能性が高く、実際には作付けの可能性がある。**SAR の限界を光学で補う、本設計の核となる分類** |
| **休耕の可能性が高い** | SAR・光学のどちらにも変化（湛水シグナル・NDVI 上昇）が見られない筆 | — |

### 【期待する出力】

- **筆単位の3段階判別マップ**（作付け / 要確認 / 休耕の色分け）
- 「要確認」に分類された筆のリスト（現地確認の優先順位づけに使う）

### 【なぜこの手法・分類を選んだか】

Step1 の目的（農業委員会の現地確認負担の軽減）を踏まえると、「衛星が休耕地と判定した場所に確認に行ったら実際は作付けされていた」という誤判定は、ツールへの信頼を損ない、本来の目的に逆行する。そのため、SAR 単独では判断がつかないケースを安易に「休耕地」に含めず、光学による補完情報がある限り「要確認」として独立させ、誤って休耕地に分類するリスクを抑える設計とした。

## 5. 検証・社会実装（Step5）

### 【検証方法】

相馬市・南相馬市内から候補地点を1〜2箇所選び、GEE 上で Sentinel-2 の True Color 画像（自然な色合いの画像）を用いて、実際に水田がどう見えるか（茶色 → 緑、または変化なし）を目視で確認する。

これを SAR（VH）・光学（NDVI）による自動判定の結果と突き合わせ、Step4 の3段階分類（作付け / 要確認 / 休耕）が実際の見え方と整合しているかを検証する。

この検証方法はいまいちな気がする。仮にそれで判断できたらSAR解析が必要ないと思われるので。
それよりも、他の同じく震災などで休耕だった地域との比較とかのほうが良い気がする。その地域は東日本大震災の太平洋側に限らず海外まで目を向けても良いし、地震ではなく火災や酸性雨などの自然災害でも良い。
そして、それらの地域についてはSARの解析に加えて、実際に現状どれくらい利用できているかという統計情報を考慮して、SARの解析結果がこうだと、これくらい実際に利用できている、休耕であるなどの対応関係を見積もって、相馬市と南相馬市ではどうかを検討する。
しかも他の地域での結果があれば、閾値などの設定についても有効な示唆が得られるようになると思う。

### 【成功の定義】

完全な精度（全筆で100%正しく判定できること）は求めない。Step4 で設計した3段階の分類が、それぞれ狙い通りに機能していることを確認できれば成功とする。

上記の通り変更の必要がある。

具体的には:

- 「作付けの可能性が高い」に分類された筆が、True Color 画像で実際に緑化（生育）していれば、判定が機能していると言える
- 「要確認」に分類された筆が、True Color 画像で緑化していれば、SAR の観測間隔の限界（Step3）を光学で正しく補完できたと言える。**これは本設計の核となる部分であり、特に重視して確認する**
- 「休耕の可能性が高い」に分類された筆が、True Color 画像でも変化が見られなければ、判定が機能していると言える

### 【限界の明記】

候補地点1〜2箇所・目視確認という小規模な検証であり、統計的な精度（正解率など）を主張できるものではない。あくまで「3段階の分類の考え方が機能するかどうか」の一次的な確認と位置づける。

上記の通り、他の地域との比較であるためあくまで参考程度に止まる。機械学習的にデータが膨大であれば、そのモデルの妥当性検証などもできそう。

### 【主な利用者と価値】

**1. 農業委員会・農政担当者**

南相馬市の農業委員会は、毎年広大な農地を現地確認する必要があり、大きな労力とコストがかかっている。衛星データによる3段階分類（作付け / 要確認 / 休耕）を使えば、現地確認の優先順位づけができ、特に「休耕の可能性が高い」農地から優先的に確認することで、全農地を一律に歩く従来のやり方より効率化できる。

**2. 農地利用予定者（新規就農者・農業法人など）**

借り手・買い手となる利用予定者にとっても、現地を訪れる前に候補地の農地利用状況（作付け・休耕の傾向）を把握できる一次的な判断材料となりうる。ただし、Step5 で述べたとおり本ツールは正解率などの精度保証を行っておらず、特に「要確認」に分類された農地を投資判断のような重い意思決定にそのまま使うべきではない。あくまで「現地訪問すべき候補地を絞り込む一次スクリーニング」として位置づけ、最終的な判断は現地確認や自治体への問い合わせと組み合わせることを前提とする。

ここについては変化がないと思う。

### 【自治体（非専門家）が使える形にする工夫】

現時点の MVP（3段階分類の地図出力）は、GIS やリモートセンシングの専門知識がなくても、色分けされた地図を見るだけで「どこを優先的に確認すべきか」を判断できる設計を目指す。ただし、分類の閾値（σ⁰ の 5 dB 落ち込み、NDVI 0.4 など）の妥当性検証や、年による調整は専門知識を持つ担当者が継続的に行う必要がある。

他の地域でのSAR結果と、現在はどう利用されているかを対応関係で示すとわかりやすいと思う。

### 【費用対効果】

Sentinel-1・Sentinel-2 はいずれも無料で公開されている衛星データであり、GEE の利用も研究・非営利目的であれば無料枠で利用できる。そのため、追加コストは主に解析用の人員（データ処理・検証）であり、毎年の全農地現地確認に比べると、継続的な運用コストは小さいと見込まれる。ただし、初期のシステム構築・筆ポリゴンデータの整備・検証作業には一定の人的コストがかかる。

### 同一座標での確定値（Inspector のクリック誤差を排除）

Inspector のクリックでは同一ピクセルを再現できないため、`reduceRegion` で座標を固定して計測した。
基準地点: **140.93508, 37.60020**（scale 10）

| 項目 | 値 |
|------|-----|
| NDVI (B5/B4・罠あり) | 0.5342 |
| NDVI (B8/B4・正しい) | 0.8093 |
| **罠①の過小評価量** | **0.2751** |
| VH 修正前 mean（8月・3枚） | -17.3758 dB |
| VH 修正後 median（7-8月・5枚） | -18.3423 dB |
| **前処理変更による差** | **-0.97 dB** |

median が mean より約1 dB暗いのは、平均が明るい外れ値に引っ張られていたことを示す。
スペックル低減が意図どおり機能している。

### 変動要因の切り分け（閾値設計に直結する）

当初「前処理変更で約3 dB動いた」と読んだが、同一座標で測り直すと前処理の効果は約1 dBだった。
3 dB の差は**場所の違い（約200m）**によるものだった。

| 要因 | 変動量 |
|------|--------|
| 前処理の違い（mean → median・期間拡大） | 約 1 dB |
| **200m 離れた地点間の空間ばらつき** | **約 3 dB** |
| 3地点間（数km）の空間ばらつき | 約 6 dB |

**空間ばらつきが前処理の影響の約3倍大きい。** 閾値 -15 dB に対して隣接ピクセルが 3 dB 揺れるため、
**ピクセル単位の判定は原理的に安定しない**。

→ 圃場単位の空間集計（Zonal Statistics）が必要。これが筆ポリゴンを使う2つめの理由になる
（1つめは市街地の除外。下記「市街地の誤検出」参照）。

### 罠①の誤判定量の定量（最も重要な発見）

過小評価量は一定ではなく、**植生が薄い側で拡大する**。

| NDVI（B8/B4） | 過小評価量 |
|---------------|-----------|
| 0.8882（地点2・濃い） | 0.2015 |
| 0.7989（地点3・やや薄い） | 0.2775 |

休耕判定の閾値は 0.35（罠あり版）／0.40（修正版）。過小評価が 0.20〜0.28 あるため、
**真の NDVI が概ね 0.40〜0.60 の農地が「休耕」と誤判定される**。
これは生育初期の農地・低バイオマスの畑・雑草の生えた休耕地という、**判別が最も難しい領域**に一致する。

つまり罠①は「判定が一番シビアな場所で誤差が最大化する」性質を持つ。単なる値のズレではない。

> 実測2点からの傾向であり、外挿には追加サンプルが必要（未検証）。

### 罠②についての補足（想定と実測の食い違い）

配布コードのコメントは「昇交/降交が混在」としているが、**実測では混在していなかった**。

- `s1.filter(ee.Filter.eq('orbitProperties_pass','ASCENDING'))` はコレクションが空になった
  （`ImageCollection.getRegion: No bands in collection.`）
- DESCENDING のみの平均 `-12.399385766569162` が、フィルタなしの平均と小数点以下まで完全一致
- したがって 2024-08-01〜08-31・このROIで取得できるシーンは全て DESCENDING

**結論**: 罠②は「現に誤った値を生んでいる欠陥」ではなく、**フィルタが無いという潜在的欠陥**である。
期間やROIを変えた時点で ASCENDING が混入し結果が変わるため、再現性の欠陥として修正する必要がある。
教材の修正版が期間を 2024-07-01〜08-31 に広げているのは、これと関係すると考えられる（未確認）。

- Console 出力『軌道の内訳』の実測値: **`{DESCENDING: 3}`**（ASCENDING は0枚）

**副産物の発見**: 8月の1ヶ月で S-1 は3枚しかない。3枚の平均ではスペックルが十分に低減されない。
期間を広げる（教材修正版は 2024-07-01〜08-31）ことは、軌道統一とは別にスペックル対策としても必要。

### 罠③についての補足（欠陥の実体）

閾値のずれではなく、**判定そのものが実行されていない**。

- `s1_vh_mean` は -12.4 dB（負値）。`log10()` の結果が masked になることを Inspector で確認
- マスクは `.lt(-20)` および `.and()` を通過しても伝播するため、`fallow_mask` は ROI 全域でマスク
- 結果として休耕地レイヤは1ピクセルも出力しない。**それでもエラーは一切出ない**
- Console 出力『休耕判定に該当したピクセル数』の実測値: **`{NDVI: 0}`**（ROI 全域で0件）

**エラーも警告も出ないまま、出力が完全にゼロ**。「エラーが出ない＝正しい」ではないことの最も明確な実例。

### 光学とSARを両方使う理由の実例（地点3）

地点3: NDVI(B8/B4) = 0.7989、VH = **-18.12 dB**。他の2地点（-12〜-13 dB）より約6 dB暗い。

修正版の判定条件「NDVI < 0.40 かつ VH < -15」に対して、この地点は
**VH条件を満たしているのに NDVI条件で救われている**。

- SARだけで判定していたら → 休耕と誤判定
- 光学だけで判定していたら → 正しく作付と判定
- 両方のANDだから → 正しく作付と判定

片方のセンサでは誤る地点が実在することを示せた。Step2 の物理仮説（データフュージョンの必要性）の根拠になる。

暗い原因は林冠下の水面の影響やバイオマス差などが考えられるが、**これは仮説**。
確定には時系列（5月の湛水期）の確認が必要。

### 計測地点2 の物理的解釈（正しいコードでの答え合わせ）

NDVI(B8/B4) = 0.8882、VH = -12.4 dB。夏季に高い NDVI と強い体積散乱が同時に成立しており、
**明確に作付中の農地**と判定できる。修正後のコードでもこの地点は休耕と判定されず、整合する。

### 閾値設定への示唆（Step5 で使う）

3地点の VH は -12.40 / -13.30 / -18.12 dB で、**約6 dB の空間ばらつき**がある。
修正版の閾値 -15 dB はこのばらつきのほぼ中央に位置する。

地点4（140.93285, 37.59918）では VH = **-15.1197 dB** で、閾値 -15.0 を **0.12 dB** しか下回っていない。
ほぼ境界線上であり、SAR側の判定は事実上不安定。この地点が休耕と誤判定されずに済んでいるのは
NDVI = 0.8351 が条件を外したためで、SAR単独では判定が揺らぐ。

閾値の妥当性検証が Step5 の課題。空間ばらつき3 dBに対して 0.12 dB の余裕は意味を持たないため、
圃場単位の集計値に対して閾値を適用する設計に変える必要がある。

### 8. 修正後に発見した追加の欠陥（配布コードの罠①〜③に含まれないもの）

### 市街地の誤検出

修正版の休耕判定は ROI 全域で 5,119 ピクセル（scale 100 → 5,119 ha ≒ 51.2 km²、ROI の約12%）を検出した。
土地被覆データと突き合わせた結果、**その 91.5% が非農地**だった（水域58.1%・市街地17.6%・草地7.8%・裸地5.8%・樹林2.1%）。
地図上では赤い領域が南相馬市の市街地と道路網を正確にトレースしており、目視でも誤検出が確認できる。

- 市街地中心部に赤が密集
- 国道6号・常磐道（E6）に沿って線状に伸びる
- 集落が点在する範囲に斑点状に集中
- 森林・山地（西側）はほぼ赤なし → 判定条件自体は正しく効いている

**物理的な原因**: 判定条件は「低NDVI かつ VH が暗い」。

| 対象 | NDVI | VH | 判定 |
|------|------|-----|------|
| 森林 | 高い | 明るい（体積散乱） | 除外（正しい） |
| 作付農地 | 高い | 明るい | 除外（正しい） |
| **舗装路・平滑な屋根** | **低い** | **暗い（鏡面反射）** | **誤検出** |
| 休耕農地 | 低い | 暗い〜中 | 検出（本来の目的） |

SAR で建物が明るく見えるのは壁と地面が作る角のダブルバウンス。
**平らな屋根や道路は入射波を反射して衛星に戻さないため、水面と同程度に暗くなる。**
低NDVIと組み合わさると休耕農地と区別できない。

**海域が最大の誤検出源（58.1%）。** ROI 北部（相馬市側・松川浦周辺）を表示すると、
赤い領域の東端と北端が**直線**になっている。これは ROI 境界（経度141.02・緯度37.80）であり、
**海が ROI の限界まで塗られている**ことを意味する。

当初「`clip(roi)` で東端が海岸線とほぼ一致するため外洋は範囲外」と判断したが、これは誤り。
その判断に使った画面が南相馬市を中心に切り取られており、相馬市側と ROI 東端の海の帯が
画面外だった。**目視は視野の外を検証できない。** 定量化（土地被覆別集計）で初めて主因が判明した。

### 土地被覆別内訳の実測（ESA WorldCover v200）

**休耕判定 5,119 件の内訳**（合計 5,040.1。差分は土地被覆データの無い画素）

| クラス | 土地被覆 | 件数 | 割合 |
|--------|---------|------|------|
| 80 | **水域** | 2,928.2 | **58.1%** |
| 50 | **市街地** | 889.1 | **17.6%** |
| 40 | **農地** | 427.9 | **8.5%** |
| 30 | 草地 | 391.7 | 7.8% |
| 60 | 裸地 | 293.2 | 5.8% |
| 10 | 樹林 | 108.0 | 2.1% |
| 90 | 湿地 | 2.0 | 0.04% |

**農地は 8.5% のみ。非農地が 91.5%。** 目視では市街地のトレースが目立ったが、
面積では水域が3倍以上大きい。ROI 東端（経度 141.02）に含まれる海の帯と、
相馬市側の海岸・河口部が効いていると考えられる。

**クラス別の検出率**（ROI 全体 52,655.3 件に対する各クラスの検出割合）

| 土地被覆 | 検出率 | 物理的な読み |
|---------|--------|-------------|
| **水域** | **88.4%** | 鏡面反射で VH が極端に暗く NDVI も低い。条件をほぼ完全に満たす |
| 裸地 | 66.0% | 低NDVI＋平滑面。休耕地と物理的に区別できない |
| 市街地 | 18.3% | 平らな屋根・舗装路が該当。壁のダブルバウンス部分は明るいため全部は拾わない |
| 草地 | 13.8% | 一部が該当 |
| **農地** | **3.7%** | 本来知りたい数字 |
| 樹林 | 0.37% | ほぼ除外。判定条件自体は正しく機能している |

水域 88.4% と樹林 0.37% という両極が、**条件式は物理的に正しく働いており、
問題は適用範囲だけである**ことを示している。

> WorldCover は2021年・10m解像度の推定値であり、それ自体に誤差を含む。
> 正解データではなく参照データとして扱う。

### 単位・スケールの罠（自分が引っかかった例）

当初「5,119 件 = 5,119 ha = 51.2 km²」と換算したが、**これは誤り**。

ROI 全体の件数 52,655.3 に対し ROI の地理的面積は約 415 km²（41,550 ha）。
したがって **1件あたり約 0.79 ha**。1 ha ではない。

原因は `reduceRegion` の `scale: 100` が EPSG:4326 で解釈され、緯度37.7°では
経度方向が縮むこと（1/cos(37.7°) ≒ 1.26 倍の差）。

| 項目 | 誤 | 正 |
|------|-----|-----|
| 休耕判定の面積 | 51.2 km² | **約 40 km²（4,039 ha）** |
| ROI に占める割合 | 12.3% | **9.7%** |

比率（58.1% 等）は分子・分母が同じ計算のため影響を受けない。
**面積に換算する場合は投影法と scale の解釈を必ず確認する。**

### 本来報告すべき数字（農地に限定した場合）

| 項目 | 件数 | 面積換算（×0.79） |
|------|------|-----------------|
| ROI 内の農地 | 11,655.6 | 約 **9,196 ha** |
| うち休耕疑い | 427.9 | 約 **338 ha**（農地の 3.7%） |

**4,039 ha ではなく 338 ha。約12倍の差。**
筆ポリゴンで範囲を限定するかどうかで、自治体に報告する数字の桁が変わる。

### e-Stat 耕地面積との突き合わせ結果

| 出典 | 農地面積 | データの性質 |
|------|---------|-------------|
| e-Stat 耕地面積（2市計・令和6年） | **10,170 ha** | 県計からの按分（加工統計）・3桁丸め |
| WorldCover クラス40（ROI内・2021年） | **約 9,196 ha** | 10m推定分類・0.79 ha/件で換算 |
| 比 | **0.90** | |

**結論: 言えることは「桁が一致した」までである。**

ROI は矩形で行政区界を覆っていないため、当初「部分的な範囲で90%は高すぎる」と考えたが、
両側に大きさ不明の誤差要因があり、**一致度そのものに意味を持たせるべきではない**。

| 誤差要因 | どちら側 |
|---------|---------|
| 市町村値が県計からの按分（加工統計） | e-Stat |
| 3桁丸め（±5 ha 程度） | e-Stat |
| ROI が矩形で行政区界と一致しない。相馬市は北へ、南相馬市は南西へ ROI 外に伸びる | 比較の枠組み |
| ROI 西端外の山地には農地が少ないため、矩形でも沿岸平野の農地を多く捕捉している可能性 | 比較の枠組み |
| 年次が異なる（2021 vs 2024） | WorldCover |
| 10m解像度の分類誤差。休耕地を草地（クラス30・ROI に2,849件）に分類する可能性 | WorldCover |
| 0.79 ha/件という近似換算 | 自分の計算 |

**得られた確認**: ROI 設定と面積換算に桁レベルの誤りは無さそうである。
**得られない確認**: 農地面積の定量的な妥当性。90% という数値を根拠に何かを主張することはできない。

→ 定量的な検証には筆ポリゴンによる面積算出が必要（ポリゴン面積の合計なら換算誤差が発生しない）。

### 結論: 筆ポリゴンは必須

**約4,039 ha という数字はそのまま使えない（非農地が91.5%）。**

#### 筆ポリゴンとは

農林水産省が公開する**農地1区画ごとの境界ポリゴンデータ**。
「筆（ひつ）」は土地登記の単位で、登記簿上の1区画の土地を「一筆」と数える。
つまり田や畑1枚ごとの輪郭を記録したベクタデータ。

| 項目 | 内容 | 出典 |
|------|------|------|
| 内容 | 1筆ごとの境界ポリゴン。圃場単位の集計に最適 | `exercises/week4_exercise.ipynb` PART B③ |
| 取得先 | `open.fude.maff.go.jp` | 同上 |
| 取得先（別） | https://www.maff.go.jp/j/tokei/porigon/ 都道府県ごとに Shapefile / GeoJSON | `resources/data-guide.md` |
| 取得先（別） | geospatial.jp「農地筆ポリゴン2021（WGS84変換版）」 | `resources/候補エリア選定_相馬南相馬.md` |
| 座標系 | JGD2011 系 等（`schedule.md` は EPSG:2451 と記載） | `exercises/week4_exercise.ipynb` |
| サイズ | 都道府県単位で数十MB | `resources/data-guide.md` |
| 読み込み | `geopandas.read_file()` | 同上 |
| 目視確認 | eMAFF 農地ナビ（map.maff.go.jp） | `resources/候補エリア選定_相馬南相馬.md` |

> 配布ファイルの正確な EPSG は未確認。Sentinel-2 は EPSG:32654（UTM 54N）なので、
> 揃えないとポリゴンとピクセルの境界がずれる（＝`schedule.md` の罠④「ミクセル」）。

#### 筆ポリゴンが解決する3つの問題

| 問題 | 解決の理由 |
|------|-----------|
| 非農地91.5%の混入 | ポリゴンが農地にしか存在しないため、海・市街地・森林が構造的に除外される |
| 空間ばらつき3 dB | 1筆内のピクセルを平均すればノイズが潰れる（Zonal Statistics） |
| **面積換算の単位誤り** | **ポリゴンの面積属性を合計すれば ha が直接出る。ピクセル数からの換算が不要** |

3つめは今回実際に踏んだ誤り（1件 = 0.79 ha）への対策になる。
ピクセルを数える限り投影法の解釈ミスが起きるが、筆単位なら桁を間違える余地がない。

`schedule.md` の Week 4 は罠④として「筆ポリゴン（EPSG:2451）を再投影せず重ねてミクセル発生」を
挙げていた。配布コードには含まれていなかったが、**筆ポリゴンが無いこと自体がより大きな欠陥**だった。
Step3 で筆ポリゴンを必須とする実測的な根拠が取れた。

### 相談1: 湛水検出の基準値と閾値の実務的な定義

- **状況**: 湛水の判定を「4月の乾田状態を基準として 5 dB 以上の低下」と設計した。ROI 内の観測は
  12日等間隔（2024年4〜8月で13観測、すべて相対軌道番号46）であることを GEE で確認済み。
- **仮説**: 4月を基準に含めなければ、初観測（05-12）時点で既に湛水していて急落が検出できない。
  また実測では約200 m 離れた地点間で VH に約3 dB の空間ばらつきがあり、5 dB は筆単位で
  平均しなければノイズと分離できない水準だと考えている。
- **確認したいこと**: 圃場単位で平均した後、5 dB という閾値は妥当か。実務では湛水を
  どの指標・どの水準で定義しているか。

### 相談2: 転作田と真の休耕の分離

- **状況**: 湛水検出は物理的に水稲を捉えるため、田で麦・大豆等を作る転作田は湛水せず
  「休耕」側に落ちる。南相馬市は田耕地面積 5,690 ha に対し水稲作付面積 950 ha（出典未特定）で、
  差が非常に大きい。
- **仮説**: この差の大部分は転作であって休耕ではないと考えている。転作面積の統計で補正するか、
  NDVI 時系列の形状（水稲と麦・大豆で立ち上がり時期が違う）で分離できるのではないか。
- **確認したいこと**: 実務では転作田と休耕をどう分離しているか。衛星データだけで可能か、
  申請情報との突き合わせが前提になるか。

### 相談3: 判定は必要十分条件か（2026-09-05 追加）

- **状況**: Step4-5 の3段階分類について、「水稲作付の可能性が高い ⟺ 稲作が行われていた」
  「水稲作付が確認できない ⟺ 休耕地」が成り立つかを検討した。
  **チーム内では当初、この2つを必要十分条件として扱っていた。**
- **見直しの結果**: **どちらも必要十分条件ではない。** 反例が存在する。
  しかも一方は本書内で既に否定されていた。

**経緯**

「水稲作付が確認できない ⟺ 休耕地」は、`analysis_doc.md` Step4【判定と統計の対応関係】が
既に「本クラスは真の休耕・耕作放棄・保全管理・一部の転作の混合」と明記しており、
**混合であると書いた時点で ⟺ は成立していなかった。** 用語の統一（9/5）まで
クラス名が「休耕の可能性が高い」だったため、名前に引きずられて必要十分と扱っていたと考えられる。
クラス名を「水稲作付が確認できない」に変えたことで、この矛盾が表面化した。

「水稲作付の可能性が高い → 稲作」のほうは反例が少なく見落としやすいが、
**Step1 が自ら定義した5状態の中に確実な反例がある。**

**反例の一覧**

| 方向 | 反例 | 確度 | 根拠 |
|------|------|------|------|
| 作付→稲作 | **作付実証での水稲試験栽培** | 確実 | 湛水するため本格作付と区別できない。Step1 の5状態と直接矛盾する |
| 作付→稲作 | **飼料用米・WCS 用稲** | 確実 | 稲作だが主食用米の作付統計には入らない。一次検証が系統的にずれる |

## 付録D: 雲量フィルタの検証記録（2026-08-30）

> 付録C ① のフィードバックを受けて実施した実測検証。
> `analysis_doc.md` Step3 の雲量フィルタ設計を見直すための根拠。

### 背景: 2つの雲量が別の粒度で存在する

Sentinel-2 の雲情報は2箇所に別の形で存在する（SAR には雲量の概念自体が無い）。

| | `CLOUDY_PIXEL_PERCENTAGE` | `SCL` |
|---|---|---|
| 種別 | Property（メタデータ） | Band（画素値・20m） |
| 粒度 | 1シーンにつき値ひとつ | 画素ごとの分類（0〜11） |
| 対象範囲 | **MGRS タイル全体（110km 四方）** | 切り出した任意の範囲 |

ROI は約 415 km²、タイルは約 12,100 km²。**ROI はタイルの約29分の1**しかない。
現行設計はタイル全体の雲量で足切りしているため、ROI の状態を反映していない。

**注記**: 両者は同じ ESA の処理系による雲判定に由来するため、これは独立検証ではない。
Sen2Cor の雲判定自体が誤っていれば両方が同時に誤る。今回検出できたのは
「集計範囲の違いによる矛盾」のみである。

### 検証コード

```javascript
var roi = ee.Geometry.Rectangle([140.85, 37.55, 141.02, 37.80]);

var s2 = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(roi)
  .filterDate('2024-04-01', '2024-09-01');

print('(1) ROIに交差する全シーン数', s2.size());
print('(2) CPP<20 を通る枚数', s2.filter(ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 20)).size());

function scoreScene(img) {
  var scl = img.select('SCL');
  var bad   = scl.eq(3).or(scl.eq(8)).or(scl.eq(9)).or(scl.eq(10)); // 雲影/雲中/雲高/巻雲
  var valid = scl.neq(0);                                            // 0 = NO_DATA
  var clear = valid.and(bad.not());
  var stats = ee.Image.cat([clear.rename('clear'), valid.rename('valid')])
    .reduceRegion({ reducer: ee.Reducer.sum(), geometry: roi,
                    scale: 60, maxPixels: 1e9, bestEffort: true });
  var v = ee.Number(stats.get('valid'));
  var c = ee.Number(stats.get('clear'));
  return img.set({
    date: img.date().format('YYYY-MM-dd'),
    cpp:  img.get('CLOUDY_PIXEL_PERCENTAGE'),
    roi_clear_frac: ee.Algorithms.If(v.gt(0), c.divide(v), 0),
    roi_valid_px: v
  });
}

var scored = s2.map(scoreScene);
print('日付', scored.aggregate_array('date'));
print('タイル雲量 CPP', scored.aggregate_array('cpp'));
print('ROI内クリア率', scored.aggregate_array('roi_clear_frac'));

var wasted = scored.filter(ee.Filter.gte('CLOUDY_PIXEL_PERCENTAGE', 20))
                   .filter(ee.Filter.gte('roi_clear_frac', 0.7));
print('(3) CPP>=20 だが ROI は7割以上クリアなシーン数', wasted.size());
```

**計測条件**: ROI `[140.85, 37.55, 141.02, 37.80]`（`analysis_doc.md` の現行値。東端の海域混入は既知の未修正事項）／
期間 2024-04-01〜2024-08-31／`COPERNICUS/S2_SR_HARMONIZED`（L2A）／集計スケール 60m／
クリア判定の閾値 0.7（仮置き）。実行日 2026-08-30。

### 主対象を農地利用予定者に一本化した理由（9/4）

改訂版までは「農業委員会・農政担当者」と「農地利用予定者」の2者を並置していた。
W6 時点の本文 Step1 にも「どちらを主目的とするか確定する必要がある」という要確認が残っており、
両方を併記する形で先送りしていた。

**一本化した理由は、両者が求める出力の粒度が異なるためである。**

| 利用者 | 求める情報 | 必要な出力 |
|--------|-----------|-----------|
| 農業委員会・農政担当者 | 現地確認に行くべき筆はどれか | 優先順位づけ。**二値＋確信度で足りる** |
| 農地利用予定者 | この農地は今どういう状態で、使えるようになるまでに何が必要か | **段階の情報が要る** |

粒度の細かい後者に合わせて設計すれば、前者の用途は副次的に満たせる。逆は成り立たない。
したがって主対象を利用予定者に置き、**出力仕様をそこから決める**こととした。

**却下した案**: 2者を並置したまま、出力を二値＋確信度にする案。
Step5【費用対効果】が農業委員会の現地確認コスト削減で組まれているため、こちらのほうが
改訂量は小さい。しかし付録Eの発見2・4により、南相馬市では**二値では実態を表せない**ことが
確定したため、改訂量の小ささを理由に採ることはできないと判断した。

**副作用（未処理）**: Step5【主な利用者と価値】と【費用対効果】は農業委員会を前提に
組まれたままであり、Step1 と不整合。下記「未反映（要チーム判断）」を参照。

### 判定クラス名を水稲基準へ統一（9/5）

**発端**: 「今回の判定は米の作付けなのか休耕地なのかの判定か」というチーム内の確認。
確認したところ、**Step1 の用語と Step4 の判定内容が一致していなかった。**

| | 記述 | 実際に判定していること |
|---|------|---------------------|
| 改訂前の Step1 | 耕作あり / 耕作なし | — |
| Step4-3 の条件 | — | 4月比で VH σ⁰ が 5 dB 以上低下（＝**湛水**の検出） |

湛水するのは水を張る作物、すなわち**水稲**である。麦・大豆・ブロッコリー等の転作作物は
作付けされていても湛水しないため、「耕作あり」に入らない。**「耕作の有無」ではなく
「湛水の有無」を見ている**というのが正確な記述である。

**変更したクラス名**

| 旧 | 新 |
|----|----|
| 作付けの可能性が高い | **水稲作付の可能性が高い** |
| 要確認 | 要確認（変更なし） |
| 休耕の可能性が高い | **水稲作付が確認できない** |
| 判定不能 | 判定不能（変更なし） |

「休耕」を避けたのは、このクラスが**真の休耕・耕作放棄・保全管理・一部の転作の混合**であり、
休耕と読めてしまうと誤った断定になるためである。「確認できない」は観測の限界をそのまま表す。

**この変更で顕在化した問題（未確認事項 #16 として登録）**

南相馬市には転作が実際に存在する（大豆 129.7 ha、ブロッコリー 47.8 ha、なたね 20.2 ha 等）。
これらは湛水しないため現地確認対象へ計上される。すなわち **r（要確認率）が過大に出る。**

9/5 に決めた「r × N を実測して追加分類の要否を判断する」という方針は、この過大評価を
そのまま使うと**必要のない追加分類に進む判断をしてしまう。** 転作分の扱いを決める必要がある。
これは付録B の相談2「転作田と真の休耕の分離」および未確認事項 #2 と同根の問題であり、
**第1回メンターレビューで未回答のまま残っている論点**でもある。

**相馬市では影響が小さいと見込まれる**（推論）。対象を田に限定すれば水稲がほぼ全量を
占めると考えられるため。ただし相馬市の転作面積は未確認であり、裏取りはしていない。

### 課題B のアプローチを「判断ドリブン」へ変更（9/5・チーム判断）

9/4 時点では「合宿中に5段階の判別に取り組み、到達点を実測する」としていた。
9/5 に**アプローチを変更**した。下の 9/4 記録は経緯として残す。

**変更内容**: 南相馬市にもまず2値分類を適用し、**「耕作なし」に落ちた筆の量で、5分類を
解析でやるか現地確認でやるかを決める。**

| 「耕作なし」の筆数 | 判断 |
|---|---|
| 現地確認で回れる規模 | 解析での5分類は不要。現地に行って5状態を確認すればよい |
| 現地確認で回れない規模 | 解析での追加分類が必要。手法を追加で検討する |

**変更した理由**

9/4 の設計は「5段階に分けること」自体を目標に置いていたが、これは**手段を目的にしていた**。
利用予定者にとって必要なのは5段階のラベルそのものではなく、「見に行くべき農地がどれか」が
絞り込まれることである。絞り込んだ結果が現地確認で回れる量なら、**5分類は人が現地で行えばよく、
解析で解く必要がない。** 解析で解くべきかどうかは、実測しなければ決められない。

したがって Full の到達内容を「5段階に分けること」から「**5段階に分ける必要があるかを実測で
判断すること**」へ置き換えた。判断には既存の費用対効果の枠組み（r × N）をそのまま使える。

**副次的な効果**: 9/4 時点で「未反映（要チーム判断）」に挙げていた
「Step5【費用対効果】が農業委員会を前提に組まれており Step1 と不整合」という問題が、
**費用対効果の試算が課題B の判断そのものになった**ため、構造的に解消される見込みである。
ただし便益の記述（現地確認コスト削減）は農業委員会向けの表現のままであり、
利用予定者向けの記述への書き換えは未実施。

**スケジュール**

| Phase | 時期 | 対象 | 内容 |
|-------|------|------|------|
| Phase 0 | 合宿前（〜9/7） | 相馬市・ROI 内の田のみ（8,581筆） | 小さい領域でパイプラインが最後まで通ることを確認 |

### 課題B に取り組む方針の決定（9/4・チーム判断）

**5段階判別は合宿期間中に着手する。** 分離可能かどうかの見通しは立っていないが、
目標としては5段階を掲げ、実際に手を動かして到達点を測る方針とした。

判断の理由は、**到達できなかったこと自体が結果になる**ためである。どの区分までが分離でき、
どこから分離できなかったのか、その原因が観測量の限界（この波長・偏波では届かない）なのか
手法の限界（特徴量設計・分類器の問題）なのかを切り分けられれば、次に何を観測すべきかが示せる。
「やらなかったので分からない」と「やったが届かなかった、理由はこうである」は別の結果である。

**取り組む順序**（難易度の低い順）

| 順 | 分離対象 | 依拠する観測量 | 見通し |
|----|---------|--------------|--------|
| 1 | 水稲 / 水稲以外 | 5月の湛水（VV・VH の急落） | **原理的に可能。** 課題A の延長線上 |
| 2 | 作付 / 非作付 | NDVI の季節振幅、7〜8月の VH 上昇 | 可能と考えられるが、放棄地の雑草繁茂と混同する恐れ |
| 3 | 保全管理 / 耕作放棄 | NDVI 季節振幅の不規則性、複数年推移 | **最難関。見通しなし。** 刈取りのタイミングを捉えられるかに依存 |

**撤退・切り替えの判断点**は合宿 Day2 15:00 の中間レビュー（Fail Fast・方針変更の最終期限）。
この時点で課題A の判別マップ初版が出ていなければ課題B には進まない。

**検証手段の制約（重要）**

順序2・3 には**照合できる公表統計が存在しない**（本付録の限界を参照）。したがって到達しても
精度を数値で示せず、二次検証（対照地による論理検証）と現地情報の照会にとどまる。
**この制約は成果発表の前に明示し、精度を主張しない。** Day5 の自治体向け提案でも同様。

## 付録F: 物理仮説の適用範囲についての検討（2026-09-05）

> 「今回の判定は水田という前提の上で、稲作の収穫後か休耕地かを判定できるという認識か」という
> チーム内の確認から始まった検討。結論は `analysis_doc.md` Step2【この仮説が成り立つ範囲】
> 【この制約への対応方針】に反映済み。本付録は経緯と、採らなかった案の理由を残す。

### 発端の問い（3つ）

1. NDVI と SAR で判定できるのは、水田という前提の上で「稲作の収穫後」か「休耕地」か、で合っているか
2. 田の中にはブロッコリー・ねぎ・じゃがいも等の野菜が作られている筆もあり、湛水しないため
   誤判定されるのではないか。収穫時期も違うため判定が誤るのではないか
3. 相馬市・南相馬市のどのあたりで稲作が多いかは分かっているはずなので、その情報と
   突き合わせながら判定すればよいのではないか

### 問い1への回答: 「収穫後か休耕か」ではない

**認識のずれが1点あった。** 観測期間は4〜8月であり、**収穫期（9月頃）は観測していない。**

判定しているのは「その年に水稲の作付サイクル（5月の湛水 → 7〜8月の繁茂）があったか」である。
単一時点の画像では「収穫後の裸地」と「休耕地」が区別できないが、**時系列を見ることで
その問題を回避している。** 「収穫後かどうかを判定している」のではなく、
「収穫後かどうかを判定する必要がない設計になっている」というのが正確な記述である。

「水田という前提の上で」という部分は正しい。Phase 0〜2 は `land_type = 100`（田）のみを対象とする。

### 問い2への回答: 指摘は正しく、想定より深刻だった

単に「誤判定される」だけでなく、**判定の土台が壊れるケースがある。**

**最も重いのは麦である。** 秋播き麦は4〜5月に NDVI が高く、6月に収穫される。
Step2 は**4月の乾田・裸土を基準値**として5月の急落を差分で定義しているため、
4月に植生がある麦作田では**基準値そのものが成り立たない。** 5月の急落を定義できない。

**次に重いのは秋冬どり野菜である。** ブロッコリー等は8〜9月定植・11〜1月収穫のため、
**観測期間4〜8月に生育期が存在しない。** 耕作されていても「水稲作付が確認できない」に落ちる。

だいずは7〜8月に NDVI が上昇するため「要確認」に入る。これは設計どおりの挙動であり、
現行設計が想定していた唯一の転作パターンだったと考えられる。

**未確認**: 上記の作型は一般的なものであり、浜通りの実作型は確認していない（未確認事項 #17）。
また南相馬市の転作実績（大豆 129.7 ha、ブロッコリー 47.8 ha 等）が**田・畑のどちらで
作られているかも資料から判別できない。** 畑であれば Phase 0〜2 の対象外であり影響しない。

### 問い3への回答: 方向性は正しいが、統計は筆単位の判定には使えない

**統計が持つのは面積の合計だけであり、位置情報がない。**
「南相馬市に大豆が 129.7 ha ある」は分かっても「どの筆が大豆か」は分からない。

使える形は3つに限られる。

| 使い方 | 可否 | 備考 |
|--------|------|------|
| 集計レベルの検証 | **可** | Step5 一次検証として実施済み |
| 事前確率としての利用 | 条件付きで可 | 農業集落別データなら市町村より細かい単位で置ける |
| 面積での事後補正 | 可 | 集計値の解釈を正す用途。個別の筆は補正できない |
| **筆単位の作物特定** | **不可** | 位置情報がないため原理的に不可能 |

> **事前確率としての利用には重大な副作用がある。**
> 一次検証の照合先として使っている統計を判定側にも使うと、**検証が自己参照になる。**
> Step5【検証方法】が掲げる「検証手段が被検証対象と同じデータ・同じ弱点を共有すると
> 循環した検証になる」という原則に正面から反する。
> 採用するなら**検証側に別の独立した情報源を用意することが条件**になる。
> これは付録D で `CLOUDY_PIXEL_PERCENTAGE` と `SCL` が独立でないと指摘したのと同じ構造の問題である。

**筆単位で作物を知る正攻法は水田台帳・営農計画書**（水田活用の直接支払交付金の申請情報）である。
筆単位で「今年この田で何を作るか」を持つ。ただし個人情報を含むため自治体しか保有できず、
`analysis_doc.md` Step5 で既に「本フェーズのスコープ外・次フェーズの課題」としている。

### 検討した対応案と評価

| # | 案 | 評価 | 採否 |
|---|----|------|------|
| A | 観測窓の拡張（4〜8月 → 通年または3〜11月） | 秋冬どり野菜も捉えられる。SAR は通年利用可、光学は雲の制約が増える | **推奨** |
| B | 判定の階層化（耕作の有無 → 水稲か否かの2段） | 転作が非作付側に落ちる問題が構造的に解消。課題B にも接続する | **推奨** |

**案 B を推す理由**: 現行の「要確認」は「SAR で判断がつかない」という**消極的な定義**である。
案 B ではこれが「**水稲以外の作物**」という積極的な意味を持つクラスに変わる。

Step4【なぜこの分類設計にしたか】が掲げる設計思想（要確認は設計者が意図して定義した状態である）
とも整合する。

さらに課題B にも接続する。案 B の第1段（耕作の有無）で保全管理・耕作放棄はいずれも非作付側に
落ちるため、**5段階分類の最難関がどこかが構造的に明確になる。**

## 付録G: SWIR（B11 / B12）の追加についての検討（2026-09-05）

> 「Step3 で光学に使うバンドは B4・B8 の2つとしたが、B11・B12 の利用も視野に入れている。
> CSV に入れられるようにして判定したい」というチーム内の提起から始まった検討。
> 結論は `analysis_doc.md` §3【追加指標の使用方針（SWIR: B11 / B12）】と
> `config.py` §3-2 に反映済み。本付録は経緯・採らなかった案・多重共線性の検討を残す。

### 発端となった資料の主張

チーム共有資料（**名称・出典とも未確認。未確認事項 #19**）に次の記述があるとして提起された。

1. B11 は土壌水分と収穫後の裸地を検出する。生育期と収穫後で大きく変化する帯域である
2. B12 を B11 と組み合わせることで、収穫後の田と休耕地の区別の精度が上がる

いずれも SWIR の一般的な性質としては整合的な主張である（水と SWIR の吸収、裸地・作物残渣の
SWIR 反射）。**ただし一次情報（論文・提供元の技術文書）を確認できていないため、
本書では「未確認の主張」として扱い、判定ルールには投入しない。**

### 発見: 主張の後半は本設計では成立しない

**「収穫後の田と休耕地の区別」は、本設計が必要としていない判別である。**

付録F 問い1 で確認したとおり、本設計は「収穫後か休耕か」を判定していない。
判定しているのは「その年に水稲の作付サイクル（5月の湛水 → 7〜8月の繁茂）があったか」であり、
**時系列を見ることで「収穫後かどうかを判定する必要がない設計」になっている。**

さらに実務上の制約として、観測期間が 4〜8月であり **収穫期（当地の水稲は9〜10月）を
一度も観測しない。** したがって現行の観測窓では、資料の主張2は評価すらできない。

主張1のうち「土壌水分」の側は 4〜8月の窓の中で意味を持つ。
**5月の湛水は SAR（VH の急落）と NDMI（上昇）の両方に現れるはずであり、
この2つが整合するかを見ることは、本設計のバグチェック（前処理の符号・単位・月ズレの検出）
として機能する。** これが Phase 0 で SWIR を入れる実際の理由である。

### 検討した案と採否

| # | 案 | 評価 | 採否 |
|---|----|------|------|
| A | B11・B12 の**生の反射率**を月別に列として出す | 隣接 SWIR 帯域で相関が高く、増える情報は主に両者の差。列数だけ倍増する | **不採用** |
| B | **正規化指標（NDMI・NDTI）として出す** | 共通の明るさ変動（日照・大気・観測幾何）が打ち消される。列数も抑えられる | **採用** |
| C | NDMI を判定ルール（湛水判定）に投入する | 5月の湛水を光学からも押さえられる。ただし閾値の根拠が無く、雲で欠測する月が判定に直結する | **見送り**（`S2_EXTRA_INDEX_POLICY = 'bug_check'`） |
| D | SWIR の取得月を9〜10月まで広げる | 資料の主張2を評価できるようになる。ただし観測窓の拡張はチーム決定事項（付録F 案A・未確認事項 #18） | **保留**（設定1行で切り替えられる形にした） |
| E | SWIR を入れない | 現状維持。バグチェックの手段が1つ減る | 不採用 |

**案 D を「保留」にして実装だけ用意した理由**: 観測窓の拡張は判定ロジックに影響する
決定事項であり、SWIR の都合で先取りするべきではない。一方で、SWIR の取得月を
判定用の月リスト（`MONTHS`）から分離しておけば、拡張の判断が出た時点で
`SWIR_MONTHS = MONTHS + [9, 10]` の1行で切り替えられる。**判定ロジックは変わらず、
影響は列が増えることに限られる。**

### 多重共線性の検討

提起と同時に「多重線形性の危険性はあるか」という問いがあった。整理すると次のとおり。

**(1) どこに相関が生じるか**

| 組 | 原因 | 性質 |
|----|------|------|
| B11 と B12 | 隣接する SWIR 帯域 | 生値では強く相関する。正規化差分（NDTI）にすれば共通成分が落ちる |
| NDVI と NDMI | **B8 を共有**（分子・分母に同じ変数が入る） | 構造的な相関。指標の定義から生じるため、データを変えても消えない |
| NDMI と NDTI | **B11 を共有** | 同上（ただし B11 の入る向きが逆であり、相関の符号は自明ではない） |

**(2) 本設計で実害になるか**

- **ルールベース判定（主軸）**: 多重共線性が問題になるのは**係数を推定する場合**である。
  閾値判定は係数推定を行わないため、相関そのものが破綻要因にはならない。
  **危険なのは別の形で現れる。「SAR で湛水」「NDVI で生育」「NDMI でも湛水」を
  3つの独立した証拠として数えると、実際には重複した情報を二重計上して
  Step4-6 の確信度が水増しされる。** 付録D で `CLOUDY_PIXEL_PERCENTAGE` と `SCL` が
  独立でないと指摘したのと同じ構造の誤りである
- **機械学習（Step5 三次検証で使う場合）**: 線形・ロジスティック回帰では係数が不安定になり
  符号が反転しうる。決定木系では予測精度は落ちにくいが、**相関する特徴量の間で
  重要度が分散し「どの特徴が効いたか」の説明が壊れる**。自治体に理由を説明する設計
  であるため、説明が壊れることは実害である
- **列数**: 5か月 × 2指標 = 10列増える。欠測パターンの組み合わせも増え、
  `n_obs` による判定不能の切り分けが複雑になる

**(3) 結論**

**Phase 0 の用途（バグチェック）で使う限り、多重共線性は危険ではない。むしろ
「相関しているはずのものが相関しているか」を確認するのがバグチェックの中身である。**
危険が生じるのは判定ルールまたは機械学習に投入した時点であり、その前に相関を実測する。

**(4) 実測の方法（未実施）**

`field_features.csv` の生成時に相関行列を出力するセルを 04 に追加した。見るのは3点。

1. NDVI 系 × SWIR 系の相関上位（B8 共有による構造的な相関の大きさ）
2. SWIR 系どうしの相関（NDMI と NDTI）
3. **`vh_may` と `ndmi_may` の相関** — 期待は負（湛水した筆ほど VH が低く NDMI が高い）。
   正または 0 付近なら、湛水シグナル・雲マスク・月の割り当てのいずれかを疑う。
   これがバグチェックとしての本来の使い方にあたる

判断の目安は `|r| ≥ 0.9` で「判定には片方だけ」。
**この 0.9 は慣行的な目安であって理論的な根拠を持つ値ではない**（VIF > 10 も同様）。
実測値が出た時点で本付録に追記する。

> **注意**: フォールバックの合成データで出る相関は、教育用に手で置いた値を測っているだけで
> 意味を持たない。判断に使えるのは GEE 実データで走ったときの値だけである。
> 相関チェックのセルはデータソースが合成の場合に警告を出す。

### チーム判断（2026-09-05）: 補助的な利用にとどめる

上記の検討を受けたチームの結論は「**使えるところで補助的に使う方針にとどめる**」である。
`config.py` の `S2_EXTRA_INDEX_POLICY` を `'bug_check'` から `'auxiliary'` に変更した。

「補助的」が何を指すかを曖昧にすると、実装のたびに解釈が揺れて後から検証できなくなる。
次のとおり定義した。

| | 内容 | 理由 |
|---|------|------|
| **許す ①** | 相関チェックと湛水の SAR / 光学 整合確認（バグチェック） | 本付録【発見】のとおり、これが Phase 0 で SWIR を入れる実質的な理由 |
| **許す ②** | 「要確認」筆について、なぜ要確認かを説明する材料 | 「要確認」は設計者が意図して定義した状態であり、説明できることが要件（Step4-6【設計判断】） |
| **許す ③** | 現地確認の優先順位づけの補助（**クラスは変えず順序のみ**） | 職員の巡回計画に効く。ただし出力の並び順は職員に見えるため、使った場合はどの指標をどう使ったかを出力に残す |
| **許す ④** | 光学が欠測した筆の状況を補足する傍証としての提示 | NDVI が欠測しても SWIR 側が残る観測がありうる。ただし判定不能の切り分け（`n_obs`）は変えない |
| **許さない ⑤** | 判定クラスを SWIR で変えること | 閾値の根拠が無い。根拠のない閾値を入れると付録D で否定した `CPP < 20` と同じ問題になる |
| **許さない ⑥** | Step4-6 の確信度スコアに加算すること | **NDVI と NDMI は B8 を共有する。独立した証拠として数えると確信度が水増しされる**（本付録【多重共線性の検討】(2)） |

**この方針で多重共線性の危険は実質的に消える。** 危険が現れるのは判定ルールと確信度
（⑤⑥）であり、そこに入れない限り相関が高くても判定は壊れない。
相関の実測（未確認事項 #20）は「判定へ投入するか」を将来判断するときの前提条件として残る。

あわせて、**SWIR のために観測窓を広げることはしない**と決めた（本付録 案D は保留から
**見送り**へ）。9〜10月へ広げるのは観測窓の拡張そのもの（付録F 案A・未確認事項 #18）が
採用された場合に限る。実装は `SWIR_MONTHS` を判定用の `MONTHS` から分離してあるため、
その判断が出た時点で設定1行で切り替えられる。

**この判断で変わらないもの**: 資料の一次情報が未特定である点（未確認事項 #19）。
`analysis_doc.md` §3 が資料の主張を引用しているため、補助利用のままでも出典の特定は必要である。

## 付録I: 対象範囲（ROI）の再設計（2026-09-05）

> 「解析計画の『候補地』とは ROI のことか、もう決まっているのか」というチーム内の確認から
> 始まった検討。結論は `analysis_doc.md` §4【対象範囲（ROI）の選定】および
> §5【段階的拡張の方針】に反映済み。本付録は経緯・却下した案・この変更によって
> 無効化される実測値を残す。

### 発端: 「候補」が3つの意味で使われていた

| 用例 | 実際に指しているもの | ROI か |
|------|--------------------|--------|
| §4【候補エリアの選定】 | 解析の対象範囲 | **ROI に相当** |
| Step5「候補地点1〜2箇所」 | 目視検証のサンプル地点 | ROI ではない |
| Step1「候補地」 | 利用予定者が探す農地＝ツールの出力 | ROI ではない |

同じ語が3つの対象を指しており、「候補地は決まっているのか」に一意に答えられない状態だった。
**用語を分ける。** 以後、解析範囲は「**対象範囲（ROI）**」、検証のサンプル地点は「**検証地点**」、
利用者が探す農地は「**候補地**」と呼び分ける。§4 の見出しも【候補エリアの選定】から
【対象範囲（ROI）の選定】へ改める。

### 旧 ROI `[140.85, 37.55, 141.02, 37.80]` の問題点

**(a) 報告単位と母集団の範囲が一致していない。**
【期待する出力】に「自治体単位の集計面積（一次検証および自治体への報告に使う）」があり、
Step5 一次検証の照合先は市町村別の作物統計である。つまり**分母は「市の全域」が前提**。
一方 ROI は矩形で市を途中で切っており、これは本書 Step4 の記述
「ROI が矩形で行政区界を覆っていない。相馬市は北へ、南相馬市は南西へ ROI 外に伸びる」
として既に限界に挙がっていた。矩形で切った集計面積は市の統計値と比較できない
（ROI 内だけの統計値が存在しないため）。

**(b) ROI と実処理範囲が一致しておらず、付録D の論法が自分に返ってくる。**
Phase 0 は `CITY_CODES = ['072095']` で相馬市のみを対象とし、画像取得範囲は
`fields.geometry().bounds()` である。ところが付録D の雲量検証は矩形 ROI 全体
（約 415 km²・南相馬市域を含む）で「ROI クリア率」を測っている。
付録D が CPP を否定した論拠は「雲を測る範囲（タイル 12,100 km²）と判定を出す範囲
（ROI 415 km²）が一致しない」であり、**同じ論法で付録D 自身の 415 km² も
Phase 0 の実処理範囲と一致していない。** 程度は小さいと考えられるが、
第2回レビューで指摘されうる箇所である（実処理範囲の面積は未計測）。

**(c) 選定根拠に挙げた参照点が範囲外にある。**
相馬市を選んだ理由として挙げた農地重心B（東・37.8041）は北端 37.80 の外、
Step5 二次検証の対照地である松川浦（37.8000）は境界上で実質的に外である。
根拠が範囲に入っていない。

**(d) 筆の選定述語が文書と実装で食い違っている。**
`config.py` は「筆の抽出は各筆の代表点（`point_lng` / `point_lat`）が ROI 内にあるかで行った」
と記載しているが、実装（`04_field_pipeline_alpha.ipynb`）は `gdf.cx[...]` で、これは
**バウンディングボックスとの交差**による選択である。なお「ROI と交差しない筆 0」という
実測は、`.cx` が交差で選ぶ以上は自明に成立するため検証になっていない。

### 採った方針: 1つの矩形に3つの役割を持たせない

旧 ROI は「母集団の範囲」「画像取得の範囲」「検証用の範囲」を1つの矩形で兼ねていた。
根拠が異なるものを1つの値で表そうとしたことが (a)〜(c) の原因である。3つに分ける。

| | 何の範囲か | 何で決めるか |
|---|-----------|-------------|
| **A. 母集団** | 判定を出す対象＝報告単位 | 報告単位と一次検証の照合先から決まる。最終的には行政区界に一致すべき |
| **B. 画像取得** | GEE から画像を取る範囲 | **A から導出**（`fields.geometry().bounds()`）。既にそうなっており変更なし |
| **C. 検証・動作確認** | 対照地・検証地点・パイプラインの疎通確認 | 参照点が入る小矩形。母集団とは無関係でよい |

### Phase 0 の ROI を約 7.2 km² にした理由

採用値 `[140.931, 37.790, 140.970, 37.809]`（約 3.43 km × 2.11 km ≒ 7.2 km²）。
出元は `resources/候補エリア選定_相馬南相馬.md` §3.1 の相馬市エリアで、**値をそのまま使う**
（新しくベタ打ちした数値を作らない）。旧 ROI の約 57 分の1。

1. **Phase 0 の目的は精度でも網羅でもなく「パイプラインが最後まで通ること」の確認**であり、
   範囲の代表性は要件でない。範囲の妥当性は Phase 2 で決めればよい
2. **農地重心A（37.7948, 140.9367）と農地重心B（37.8041, 140.9644）が両方入る。**
   相馬市を選んだ理由である「東西2つの農地重心で市内比較ができる」が、Phase 0 の時点で
   成立する（旧 ROI では B が範囲外だった）
3. **筆数が大幅に減り、`N_LIMIT` を外した全筆実行が現実的になる。**
   合宿WBS のリスク表「GEE がタイムアウトする」への事前の手当てになる
4. 上記 C（検証・動作確認の範囲）の定義そのものに一致する

### 却下した案

| 案 | 却下の理由 |
|----|-----------|
| **旧 ROI のまま Phase 0 を通す** | 実処理範囲が未計測で付録D と整合しない。415 km² 全域を対象にする必然性が Phase 0 の目的（疎通確認）に無い |
| **Phase 0 から相馬市全域（行政区界）にする** | 機能確認に不要な規模。ただし **Phase 2 では行政区界ベースを再検討する**（下記） |
| **松川浦を含むよう ROI を東へ広げる** | **効果がない。** 画像取得範囲は `fields.geometry().bounds()`（筆から導出）であり、松川浦には筆が存在しないため、ROI に含めても画像取得範囲には入らない。対照地は ROI とは独立の geometry として指定するのが正しい。→ `config.py` に `CONTROL_WATER` を新設し、対照地を ROI から切り離した |

### JA へのヒアリング（2026-09-07 予定）の位置づけ

**得られた情報の使い方の原則（推奨・チーム判断が必要）**

> **範囲を削るのではなく、出力の優先度に使う。**

理由は3つ。

1. **母集団を削ると一次検証の分母が壊れる。** 市町村別統計と照合する以上、
   一部地域を除外した集計面積は統計値と比較できない（上記 (a) と同じ構造）
2. **「車でも行きづらく情報がない」地域こそ、Step1 の価値が最大になる場所である。**
   本ツールの便益は現地確認の負担軽減と、訪問前の一次スクリーニングであり、
   情報空白地帯を除外することは価値そのものの否定になる
3. **「市街地に近く既に分かっている」地域は便益が小さいが、統計照合の分母には必要**である

したがって、判定は全域で出したうえで、**出力の並び順に「情報空白度」を反映する**案を推す。
現行の並び順は確信度の降順（【期待する出力】）であり、ここに現地情報の有無を
加えるかたちになる。ただし **`S2_EXTRA_INDEX_POLICY` の議論と同じく、
並び順を変えるものは職員に見える出力を変える。** 使う場合は何をどう使ったかを出力に残す。

**例外**（範囲を削ってよい場合）: 「そもそも農地が存在しない」「筆ポリゴンが現況と合わない」
など、**母集団の定義自体が誤っている**とわかった場合。この場合は除外ではなく定義の修正である。

## 付録J: 二次検証の再設計と、要確認率 r の扱い（2026-09-05）

> 2つのチーム内指摘から始まった検討。結論は `analysis_doc.md` §5【検証方法】二次検証
> および【費用対効果】に反映済み。本付録は経緯と、採らなかった案の理由を残す。
>
> 指摘1: 「筆ポリゴンごとの分析を適用している時点で市街地とか森林は含まれないから、
>         物理的に絶対判定できる領域を含むことにならないのではないか」
> 指摘2: 「r の定義式から、モデルがとりあえず要確認を出せばよいというふうに
>         学習されると困る。要確認はもっとも出しやすいがどっちつかずの分類であるから。
>         だけど要確認が多すぎると費用対効果が小さくなり解析の意味がなくなる」

### 指摘1: 二次検証が構造的に失敗しえない検査になっていた

**指摘のとおりである。** 改訂前の二次検証は対照地として松川浦（通年水面）・市街地・森林の
3つを挙げ、「『水稲作付が確認できない』と判定されてはならない」を検査項目としていた。
しかし母集団は `CITY_CODES` ∧ `LAND_TYPE` ∧ ROI で選んだ筆ポリゴンであり、
**市街地・森林・水面はそもそも入力に入らない。** 判定クラスが割り当てられることがない以上、
「判定されてはならない」は常に真であり、テストとして機能していなかった。

**原因は履歴である。** この3行は W4 の失敗（筆ポリゴンを使わず ROI 全域に画素単位で
閾値判定した結果、検出画素の 91.5% が非農地）を受けて書かれたもので、**当時は母集団に
市街地も森林も海も入っていた**ため有効な検査だった。その後 Step4-0（筆ポリゴンによる
範囲限定）が入り、この失敗モードは構造的に消えている。同じ節の
「この失敗が解消できたことの確認は必須項目である」も、確認するまでもなく設計上起きない。

### 一番効く直し

改訂前の導入文は「答えが物理的に確定している場所を検証地域に必ず含める」であった。
**ここに「母集団の中に」が入っていないことが穴の根本である。**

> 答えが物理的に確定している筆を**母集団の中に**必ず含める。

この一文に直すと、市街地・森林の行は自動的に不適格になり、下記の B1・B2 に置き換わる。

### ただし完全にゼロではない — ここに本物の検証対象がある

**筆ポリゴンは「制度上の農地」であって「現況の農地」ではない。** 農地台帳・空中写真判読に
基づく区画であるため、次のものは母集団に残りうる。

- 太陽光発電設備に転用された筆
- 建物・資材置き場・道路になった筆
- 長期放棄で樹林化した筆
- ため池・調整池が広がって水面にかかっている筆

つまり「市街地・森林は含まれない」は**設計上は真だがデータ上は保証されていない**。
未確認事項 #13（筆ポリゴンの取得時点と現況の乖離）と地続きである。

### 3つに分けた

改訂前の1つの表に、性質の異なる3つの目的が混ざっていた。分離する。

| | 何をするか | 失敗しうるか |
|---|-----------|-------------|
| **B1** | 母集団の健全性検査（筆ポリゴン × ESA WorldCover） | **する。** 検証になる |
| **B2** | 母集団内の確定筆による判定の検査 | **する。** 検証になる |
| **B3** | 対照地の信号を閾値の基準点にする | **しない。** これは校正であって検証ではない → Step4-3 の根拠側へ移す |

**B3 を二次検証から外した理由**: 松川浦の σ⁰ 時系列を引くこと自体には価値がある
（通年水面の VH がどの dB に出るかが分かれば、湛水判定の 5 dB がその方向に十分な落差か
どうかの傍証になる。未確認事項 #3）。しかしそれは「値の期待範囲を与える校正」であって、
「判定が誤っていないかを確かめる検証」ではない。混ぜると、校正した基準で自分を検証する
循環になる。**対照地は ROI とは独立の geometry として指定する**方針（付録I・`CONTROL_WATER`）と
整合する。

### B2 の各行の検出力（正直な評価）

3行のうち、実際に検出力があるのは1行目にほぼ限られる。

| 対照 | 検出力 | 理由 |
|------|--------|------|
| **確実に作付されている筆** | **高い** | 「水稲作付」と出なければ見落とし。Recall 側の破綻を直接検出する。ラベルが人由来（聞き取り）で衛星と独立 |
| 通年湛水・ため池化した筆 | 中 | 4月ベースラインも低いため通常は「水稲作付が確認できない」に落ちる。ベースライン処理の誤りがあるときだけ失敗する |
| 非農地に転用された筆 | 低 | 通常は「水稲作付が確認できない」に落ちて自明に通る。スペックルや混合画素で偽の急落が出た場合にのみ失敗する |

**1行目のラベルは JA ヒアリング（2026-09-07・未確認事項 #27）で取得できる可能性がある。**
「この筆は毎年作付している」という情報が数筆ぶん得られれば、それがそのまま対照になる。
J6（実態が把握しにくい地域／よく分かっている地域）と同じ聞き取りの中で拾える。

### 指摘2: 要確認への逃避を防ぐ

**現行の分類規則は残余クラス（else）になっていない。** Step4-5 は
（湛水シグナル, NDVI 上昇）の組で定義されており、要確認は
「湛水×かつ NDVI 上昇○」という**明示的な条件**で入る。この構造は維持する。

**しかし指摘の懸念は別の経路で成立する。** 閾値を通じてである。

`VH_FLOOD_DROP_DB` を厳しく（5 dB → 8 dB 等）すると、湛水判定を通る筆が減る。
作付されている筆の多くは NDVI が上昇するため、**押し出された筆は要確認へ流れる。**
このとき見落とし（作付を非作付と誤る）は減るので **Recall は上がり、同時に r も上がる。**
Recall だけを目的にすると、閾値の探索は自動的に厳しい方へ動き、要確認が膨らむ。

**退化解**

| やり方 | Recall | r | 削減率 `1 − r − k` |
|--------|-------:|--:|------------------:|
| 全筆を「要確認」にする | **1.0** | 1.0 | **−k（赤字）** |
| 全筆を「水稲作付が確認できない」にする | **1.0** | 1.0 | **−k（赤字）** |
| 全筆を「水稲作付」にする | 0.0 | 0.0 | **1 − k（最大）** |

**Recall も削減率も、単独では自明に最大化できる。** どちらか一方を目標に置いた時点で
設計が壊れる。

### 採った対応

1. **Recall と r は必ず対で報告する。** 片方だけの数値を成果として出さない
2. **閾値の探索を制約付き最小化として定義する。**
   「Recall ≥ 0.9 を満たす範囲で r を最小化する」。Recall は制約であって目的関数ではない
3. **r_max を削減率目標から逆算する。** `r_max = 1 − 削減率目標 − k`。
   r の上限を後付けの感覚で決めない
4. **退化ベースラインを必ず併記する。** 上の3行を評価表に載せ、自明解に勝っていることを示す
5. **要確認に理由コードを持たせ、r を理由別に分解する。**
   要確認が膨らんだとき、どの経路で膨らんだのかを特定できるようにする

### 採らなかった案

| 案 | 却下の理由 |
|----|-----------|
| **r に上限を設けて超えたら要確認を強制的に他クラスへ振り分ける** | 判定の根拠が「そう決めたから」になり、自治体に説明できない。Step4-6 で機械学習の `predict_proba` を却下したのと同じ理由 |
| **F1 など単一指標に統合する** | 要確認は「誤り」でも「正解」でもなく保留であり、混同行列の枠に素直に入らない。無理に単一指標にすると、保留のコストが見えなくなる |
| **Recall の目標値を下げて r を稼ぐ** | 見落とし率は運用側の許容水準が決めるものであり、削減額から逆算してよい量ではない（本書【精度とのトレードオフ】に既述） |

### 積み残し（本改訂では扱わない）

**Step4-5 の分類表に未処理の組がある。** 表は（湛水, NDVI 上昇）の4通りのうち3通りしか
明示しておらず、**「湛水○ かつ NDVI 上昇×」が暗黙に「水稲作付」へ落ちる。**
この組は物理的には保全管理のための湛水管理（未確認事項 #21）や一時的湛水にあたりうる。
現行の書き方では検出されずに水稲側へ入る。**分類設計の変更を伴うためチーム判断が必要であり、
本改訂では指摘の記録にとどめる。**
