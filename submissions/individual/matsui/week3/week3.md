# Week 3 活動記録

## 使用したNotebook

`tutorials/03_machine_learning.ipynb`

## 取り組んだ内容

Week 3では、相馬市・南相馬市のSentinel-1／2時系列データを使い、作付・休耕候補を判別する複数の方法を実行・比較した。単にモデルを動かすだけでなく、疑似ラベル、評価データ、データリーク、誤分類、閾値感度など、精度の意味を確認した。

## 1. Notebookの実行環境

- GEEへの接続と認証を行った。
- `env.py` から `setup_font` などの関数をimportした。
- `from env import ...` により、同じ `tutorials/` フォルダにあるPythonファイルの関数をNotebookで使用できる仕組みを確認した。
- VS Code／ローカル環境で日本語フォントを設定した。

## 2. 解析条件

主な設定は次の通りだった。

```text
期間: 2021-01-01〜2025-12-31
対象年: 2024年
座標系: EPSG:32654
集計解像度: 10 m
Sentinel-2雲量: 20%未満
Sentinel-1軌道: DESCENDING
Sentinel-1モード: IW
```

相馬市と南相馬市の範囲を格子に分割し、40セルを準備した。GEEから取得した画像数は、Sentinel-2が336、Sentinel-1が151だった。

年・セルごとに次の特徴量を作成し、最終的に72サンプルのデータを得た。

- `ndvi_may`: 5月のNDVI
- `vh_may`: 5月のVH
- `ndvi_aug`: 8月のNDVI
- `vh_aug`: 8月のVH
- `ndvi_summer_max`: 夏季の最大NDVI

さらに、次の派生特徴量を追加した。

- `vh_range`: 5月から8月までのVH変化
- `ndvi_growth`: 5月から夏季ピークまでのNDVI増加量

## 3. 衛星データの物理チェック

`satellite_utils.py` のガード関数を使い、次を確認した。

- VHがすでにdB値であり、二重にdB変換していないこと
- NDVIのバンドが `B8` と `B4` であること
- Sentinel-1の軌道方向を混在させないこと
- レイヤ間のCRSを揃える必要があること
- Sentinel-2の雲マスクとSARのスペックル処理を意識すること

## 4. 物理ルールによる疑似ラベル

5月のVHと8月・夏季のNDVIから、作付・休耕の疑似ラベルを作成した。

```text
作付候補: 5月のVHが湛水を示し、8月のNDVIが高い
休耕候補: 夏季最大NDVIが低い
未ラベル: どちらの条件にも当てはまらない
```

結果は次の通りだった。

```text
全サンプル: 72
作付ラベル: 4
休耕ラベル: 31
未ラベル: 37
ラベル付き: 35
```

このルールは厳密な「農地／非農地」判定ではなく、実質的には「水稲作付らしい／水稲作付ではなさそう」に近いと分かった。畑・果樹園などは農地でも湛水しないため、作付側に入りにくい。また、休耕側には裸地・道路・市街地・水域などが混ざる可能性がある。

## 5. RandomForestによる分類

疑似ラベルが付いた35サンプルを学習・テストに分け、RandomForestを実行した。疑似ラベルを正解としたテストでは、混同行列は次のようになった。

```text
[[11, 0],
 [ 0, 1]]

テスト精度: 1.00
```

ただし、疑似ラベル自体を作るために使った特徴量で学習しているため、この高精度は閾値ルールを再現しただけの可能性が高い。「精度1.0だから本当に正しい」とは言えず、循環評価に注意する必要があると理解した。

特徴量重要度と、8月NDVI・5月VHの散布図も表示し、どの値が分類に影響しているかを確認した。

## 6. 教師なし学習と異常検知

### KMeans

特徴量を標準化し、3クラスタに分けた。

```text
cluster 0: 14サンプル
cluster 1: 41サンプル
cluster 2: 17サンプル
```

各クラスタのNDVI・VH平均から、作付・植生あり、休耕・裸地、非農地などの性質を物理的に解釈した。クラスタ番号自体に意味はなく、平均値や画像を見て人間が意味付けする必要があると分かった。

### IsolationForest

`contamination=0.10` として異常検知を実行した。

```text
正常: 64サンプル
異常: 8サンプル
```

異常8件の内訳は、疑似ラベル上で休耕5件、作付0件、未ラベル3件だった。異常検知は正解ラベルを直接使わず、他と異なる特徴を持つ場所を「要確認候補」として絞り込む用途に使えると考えた。

## 7. 目視ラベルを使った精度評価

`validation_labels.csv` の目視ラベル16件を読み込んで評価した。

```text
休耕: 10件
作付: 6件

混同行列（行=真、列=予測）
[[8, 2],
 [0, 6]]

F1        = 0.857
Precision = 0.750
Recall    = 1.000
IoU       = 0.750
```

本当の作付6件はすべて検出したが、休耕2件を作付と誤判定した。

- FP（偽陽性）: 休耕を作付と誤判定し、不要な現地確認が増える。
- FN（偽陰性）: 作付を休耕と誤判定し、作付農地を見逃す。

今回はFPが2件、FNが0件だった。誤分類したセルでは、8月NDVIが比較的高く、雑草や牧草の繁茂を作付と誤認した可能性を考えた。

ただし、学習外の圃場が7件しかなかったため、評価には一部学習データも含まれている。このため、F1などの数値は楽観的な参考値であり、完全な汎化性能ではない。

## 8. 物理ルールと機械学習の比較

同じ検証セットで、物理ルール、通常のRandomForest、派生特徴量付きRandomForestを比較した。

| 指標 | 物理ルール | RandomForest | RF＋派生特徴量 |
|---|---:|---:|---:|
| F1 | 0.000 | 0.857 | 0.857 |
| Precision | 0.000 | 0.750 | 0.750 |
| Recall | 0.000 | 1.000 | 1.000 |
| IoU | 0.000 | 0.750 | 0.750 |

物理ルールは16件中7件を未判定とし、残ったサンプルでも作付をうまく当てられなかった。特に `NDVI >= 0.70` などの条件が厳しく、実データに合っていない可能性がある。一方、この小さな検証セットでは、派生特徴量を追加してもRandomForestの結果は変わらなかった。

## 9. 閾値感度分析

固定した1組の閾値だけを使うのではなく、VHとNDVIの閾値を変え、作付・休耕・未判定の件数がどう変化するか調べた。

最初から細かい範囲を見るのではなく、次の方法を考えた。

1. 広い範囲を粗い間隔で探索する。
2. 判定数が大きく変わる範囲を見つける。
3. その周辺だけ細かい間隔で再探索する。

試行中には、次の問題を経験した。

- 列名を `NDVI_th` から `NDVI_high_th`／`NDVI_low_th` に変えた後、古い列名を参照して `KeyError` が発生した。
- 3つの閾値を同時に変えた結果を、そのまま2次元の `pivot` にしたため、重複キーの `ValueError` が発生した。
- 3変数の結果を2次元グラフにするには、1変数を固定する必要があると分かった。
- 休耕判定数は主に低NDVI閾値で決まるため、VHの線が重なって見える場合があると分かった。

保存されているNotebookでは、全72サンプルに対する閾値感度表とグラフを出力できるところまで進めた。ただし、最終的に採用する閾値はまだ確定していない。

## 10. ピクセル判定と一筆判定

SARのスペックルと光学値の揺らぎを模擬し、ピクセル単位の判定と、一筆内の平均値による判定を比較した。

```text
判定が揺れたセル: 13
```

単一ピクセルではノイズによって判定が変わりやすいが、農地区画ごとに平均してから判定すると安定することを確認した。実務では、筆ポリゴンに対するZonal Statisticsが重要だと理解した。

## 11. 確信度とグレーゾーン

RandomForestの `predict_proba` を使い、作付である確率から確信度を付けた。

```text
作付（確信）: 41
休耕（確信）: 31
グレーゾーン: 0
```

今回グレーゾーンが0件だったことは、モデルが本当に完全に判断できたというより、疑似ラベルを元に学習したことで確率が極端になった可能性がある。確信度を現場巡回の優先順位に使うには、独立した正解データで確かめる必要がある。

## 12. データリークの確認

同じ `cellid` の別年データが学習側と評価側へ分かれると、似た圃場を両方で見てしまい、精度が楽観的になる可能性がある。そのため、ランダム分割と圃場単位の分割を比較した。

```text
ランダム分割の精度: 1.000
cellid単位分割の精度: 1.000
評価用: 5圃場、9サンプル
```

今回はどちらも同じ値だったが、本当の汎化性能を見るには、今後も `cellid` 単位で学習・評価を分離する必要がある。
